Is Grep All You Need? How Agent Harnesses Reshape Agentic Search

【一句话讲清楚它在说啥】
这篇论文对比了 AI Agent 在搜索时用传统 grep 命令和向量检索谁更准。结果发现，在复杂任务里，grep 反而比向量检索准确率更高，而且工具调用的方式（比如结果怎么展示给模型）影响巨大。
【详细讲给你听】
背景是现在大家都在用 AI Agent 做复杂任务，比如让它自己搜资料、调用工具、推理。最常用的方法是 RAG（检索增强生成），但很少有人系统比较过不同的检索策略（比如用 grep 还是向量数据库）在 Agent 工作流里到底谁更好。核心是这篇论文做了两个实验。实验一：用 116 个长上下文问题，对比 grep 和向量检索在四种不同 Agent 框架（Chronos、Claude Code、Codex、Gemini CLI）下的表现。关键发现是，grep 在大多数情况下准确率更高。实验二：在查询里混入越来越多无关的聊天历史，模拟真实场景中的干扰信息，结果 grep 的稳定性依然更好。更值得注意的细节是，工具结果怎么展示给模型（是直接嵌入到对话里，还是作为单独文件让模型读）对最终准确率的影响，甚至超过了检索方式本身。说白了，对于做决策智能平台的你来说，这意味着在工业场景里，有时候简单直接的精确匹配（grep）比花里胡哨的语义搜索（向量）更靠谱，尤其是在处理排产规则、工艺参数这些需要精确对应的事务上。
【关键术语小词典】
- grep / 全局正则表达式打印：一个古老但强大的命令行文本搜索工具，按关键词精确匹配。
- Agent Harness / Agent 框架：用来编排和控制 AI Agent 行为的基础软件架构，比如决定它怎么调用工具、怎么推理。
- Vector Retrieval / 向量检索：把文本转成数学向量，通过计算相似度来找到语义相近的内容，不要求关键词完全匹配。
【对你有啥用】
第一，这直接挑战了你对 RAG 的固有认知。下次跟客户聊供应链优化时，不要只吹向量数据库多智能，可以提一句“在某些精确匹配的排产规则查询上，传统 grep 可能更快更准”，这能体现你的技术深度。第二，论文里强调“工具结果如何呈现给模型”比“用什么检索”更重要。这提醒你，在设计 AI 决策智能平台的产品交互时，Agent 看到的上下文结构（比如把排程结果单独做成结构化文件）可能比算法本身更影响最终决策质量。第三，对于你关注的 AI Agent 学习路径，这篇论文提供了一个很好的研究范式：不要只看模型能力，要关注工具调用链的工程细节，这对你理解产品架构很有帮助。

【详细讲给你听】
背景是3D领域有个老大难问题：带关节的可动3D物体数据太少。比如你想训练机器人识别抽屉怎么拉开，或者让游戏里的门能真实转动，都需要大量这种带运动结构的3D模型。以前要么手工建模，要么用传统算法生成，质量都不行。这篇论文的核心思路很巧妙：他们把生成可动3D物体的问题，转化成让AI写程序的问题。具体来说，他们设计了一套专门的编程接口，大语言模型通过这个接口调用SDK来定义零件、组合几何形状、指定关节类型，甚至还能写测试代码来验证生成的模型能不能正常动。系统里还有个“约束框架”，帮LLM屏蔽掉写URDF文件、管理软件环境这些杂事，只聚焦在核心逻辑上。关键细节有三个：一是他们用这个系统生成了Articraft-10K数据集，包含超过1万个可动3D资产，覆盖245个类别；二是实验证明，这套方法比现有的专用可动资产生成器和通用编程智能体都强；三是这个数据集可以直接用在机器人仿真和虚拟现实里。说白了，这是把LLM当“3D建模程序员”用，自动产出高质量的可动3D资产。
【关键术语小词典】
Articraft：本文提出的智能体系统，自动生成带关节的3D物体。URDF：统一机器人描述格式，机器人领域常用的模型文件标准。SDK：软件开发工具包，这里指专门为3D建模设计的编程接口。
【对你有啥用】
第一，这个思路对你做决策智能平台很有启发。他们用LLM写程序来生成3D资产，本质上是用AI自动化一个需要专业知识的流程。你在供应链优化里，能不能用类似方法让LLM自动生成排产方案或BOM结构？第二，他们设计的“约束框架”值得关注。LLM容易跑偏，他们通过限制工作空间和结构化反馈来保证输出质量。这跟你做AI产品落地时，如何控制LLM输出稳定性直接相关。第三，这个数据集对制造业客户有潜在价值。电池、医药、钢铁这些行业做产线仿真或机器人调试时，需要大量可动3D模型，Articraft-10K可能成为你们和客户聊数字孪生时的素材。

背景是现在用AI写论文的工具很多，但最大的痛点是AI会编造引用、讨好用户、甚至偷偷作弊。这个ARS项目就是针对这些问题设计的。核心是4个skill：Deep Research用13个Agent做文献调研和选题，Academic Paper用12个Agent写稿和排版，Academic Paper Reviewer用7个Agent模拟期刊审稿，Academic Pipeline把这三个串成10个阶段的流水线。关键细节有三个：一是引用核验，每篇文献都要过Semantic Scholar API，用Levenshtein相似度算法模糊匹配，阈值0.7以上才算通过，实测在一篇真实论文里抓到了15个伪造引用和3个统计错误。二是完整性闸门，在Stage 2.5和4.5有两道不可跳过的检查，运行一份来自Nature论文的7项AI失败模式清单，任何被标记为SUSPECTED的问题必须变成CLEAR才能继续。三是反谄媚协议，审稿团队里的魔鬼代言人Agent会持续挑刺，它的反驳评分低于4分时写作团队不允许承认，而且攻击强度在修订过程中必须保持，防止AI为了讨好用户而放水。另外还有三层数据隔离，写作AI只能看到审稿的自然语言反馈，看不到评分标准和参考答案，这个设计灵感来自Anthropic的w2s-researcher研究。影响是这套系统把AI写论文从“能写”升级到了“可靠地写”，对学术界和工业界做知识密集型工作的人都有参考价值。
