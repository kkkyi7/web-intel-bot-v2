xAI 开源 Grok Build 代码库
xai-org/grok-build, now open source
Simon Willison · 昨天 23:59
⌄
https://simonwillison.net/2026/Jul/15/grok-build/#atom-everything

【一句话讲清楚它在说啥】
xAI 的 Grok Build 命令行工具之前被曝会偷偷上传用户整个目录（包括 SSH 密钥和密码），引发众怒后，xAI 不仅删除了所有已上传数据，还直接把整个代码库（84 万行 Rust）开源了，Apache 2.0 协议。
【详细讲给你听】
这事儿背景挺有意思。Grok Build 是 xAI 推出的一个终端编程 Agent 工具，类似 OpenAI 的 Codex 或者 Claude Code。结果上周社区炸了锅——有人在根目录跑了一下，发现它把整个家目录全上传到了 xAI 的 Google Cloud 存储桶里，包括 SSH 密钥、密码管理器数据库、文档、照片、视频，啥都没落下。用户直接骂翻了。

xAI 的反应速度还行。先是马斯克发帖说“所有已上传数据将彻底删除”，然后直接把这个功能禁用了。更狠的是，几个小时前他们直接把整个 Grok Build 的代码库用 Apache 2.0 协议开源了，目的很明确：挽回用户信任。

代码库本身挺有料。总共 84 万 4530 行 Rust 代码，只有大约 3% 是第三方依赖。里面包含了主系统提示词和子 Agent 的提示词模板，还有个自研的终端 Mermaid 图渲染器。有意思的是，它里面还“移植”了 Codex 和 OpenCode 的多个工具实现，比如 apply_patch、grep_files、bash、edit 这些，看起来 Grok Build 可以根据检测到的环境（比如用户装了 Codex 还是 Claude Code）来切换使用不同的工具集。上传到 Google Cloud 的代码还在，但已经被硬编码返回“不可用”错误了。
【关键术语小词典】
- Apache 2.0 license / Apache 2.0 许可证：一种宽松的开源协议，允许商用、修改和再分发，只要保留版权声明。
- GCS bucket / Google Cloud 存储桶：Google 云平台上的对象存储容器，类似一个网络硬盘文件夹。
- Rust / Rust 语言：一种系统级编程语言，以内存安全和性能著称，常用于构建底层工具和基础设施。
- SLOCCount / 代码行数统计工具：一个统计源代码行数的工具，排除空行和注释。
【对你有啥用】
1. 对产品判断的直接启发：Grok Build 的“默认上传数据”设计翻车，说明做 AI 编程工具时，数据隐私不是功能，是底线。你做的决策智能平台涉及制造业客户（电池、医药、钢铁），这些客户的数据敏感度极高，任何“默认上传”或“默认留存”的设计都会直接导致客户信任崩塌。下次跟客户聊产品时，可以主动强调“数据本地优先、默认不留存”，这比任何功能亮点都更能建立信任。

2. 对学习路径的参考：84 万行 Rust 的终端 Agent 代码开源了，这是你学习 AI Agent 架构的绝佳素材。你可以直接去看它的系统提示词模板（xai-grok-agent/templates/prompt.md）和子 Agent 提示词，理解它如何组织多 Agent 协作。同时，它“移植”了 Codex 和 OpenCode 的工具实现，这能帮你理解不同编程 Agent 的工具设计差异——这对你理解 AI 编程工具的产品逻辑有直接帮助。

3. 对内容产出的素材：这件事是“AI 产品翻车 + 危机公关 + 开源挽回信任”的经典案例。你可以写一篇分析，对比 Grok Build 和 Claude Code / Codex 在数据隐私策略上的差异，或者讨论“AI 编程工具的数据安全设计原则”。这既能展示你对 AI 产品的深度理解，也能吸引关注数据隐私的开发者读者。

【一句话讲清楚它在说啥】
OpenAI搞了个叫GPT-Red的系统，让AI自己跟自己玩红队攻防，自动发现并修复安全漏洞和提示注入问题，不用人工反复测试。
【详细讲给你听】
背景是现在AI安全测试主要靠人工红队，成本高、覆盖不全，而且模型更新后旧测试用例就失效了。GPT-Red的核心思路是让两个AI模型互相博弈：一个扮演攻击者不断找漏洞，另一个扮演防御者实时修补。关键细节有三点：第一，它用自我博弈机制，攻击者和防御者在对抗中共同进化，类似AlphaGo自我对弈的逻辑；第二，系统能自动生成对抗性提示（比如绕过安全限制的指令），覆盖范围比人工测试大几个数量级；第三，OpenAI声称GPT-Red发现的漏洞中有40%是传统方法漏掉的。影响方面，这意味着AI安全测试从“人海战术”转向“AI自动化攻防”，对开发者来说，以后部署模型前可能直接跑一遍GPT-Red就能拿到安全报告，不用再雇红队专家。但要注意，这种自我博弈也可能产生攻击者学会的新型漏洞，需要人工兜底。
【关键术语小词典】
- Red Teaming / 红队测试：模拟黑客攻击来找出系统弱点，传统靠人工，现在AI自己干。
- Self-Play / 自我博弈：AI通过和自己对抗来提升能力，比如AlphaGo自己跟自己下棋。
- Prompt Injection / 提示注入：故意输入恶意指令让AI输出违规内容，类似SQL注入但针对大模型。
【对你有啥用】
第一，你做的决策智能平台如果涉及大模型（比如排程算法用LLM做自然语言交互），GPT-Red的思路可以直接借鉴：让两个模型互相攻防来测试供应链优化建议的鲁棒性，比如模拟客户故意输入矛盾数据看系统会不会崩溃。第二，跟制造业客户聊AI安全时，可以举这个例子说明“我们不只是做算法，还做了自动化安全测试”，这比空谈“我们很安全”有说服力。第三，学习路径上，建议你研究一下“对抗性训练”在工业软件中的应用，比如电池生产排程里，能否用类似方法测试算法对异常订单的容错能力。

【背景知识】
传统AI红队测试靠人工找漏洞，成本高且模型一更新旧用例就废。GPT-Red的思路是让两个AI模型自我博弈——一个专门搞破坏（攻击者），一个实时打补丁（防御者），类似AlphaGo自己跟自己下棋的对抗进化逻辑。OpenAI声称这套系统能发现40%传统方法漏掉的漏洞，但注意：自我博弈也可能让攻击者学会新型攻击手法，最终还得靠人工兜底，不是完全自动化。

【一句话讲清楚它在说啥】
Google 在 Gemini API 里给托管代理加了后台任务、远程 MCP 支持等功能，让开发者能构建更可靠、可投产的 AI Agent，不用自己管基础设施。
【详细讲给你听】
背景是之前开发者用 Gemini API 做 Agent 时，很多任务需要实时响应，但实际业务里大量是耗时操作（比如供应链里的排程计算、数据清洗）。Google 这次更新核心是让 Agent 能跑后台任务，用户发个请求就能走，不用一直等。关键细节：第一，支持远程 MCP（Model Context Protocol），意味着 Agent 可以调用外部工具和数据源，比如连上你公司的 APS 系统或数据库。第二，托管模式帮你处理了部署、扩展、监控这些脏活，开发者只需写业务逻辑。第三，官方强调“生产就绪”，说明稳定性、错误处理这些坑被填了不少。影响方面，这直接降低了构建复杂 Agent 的门槛——以前你要自己搞队列、任务调度、重试机制，现在 API 层帮你包了。对做工业软件的你来说，这意味着可以把 AI Agent 更放心地嵌入到客户的生产流程里，比如让 Agent 在后台持续优化排程方案，而不阻塞前端操作。
【关键术语小词典】
- Managed Agents / 托管代理：Google 帮你管理运行、扩展和监控的 AI Agent，你只管写逻辑。
- MCP / 模型上下文协议：一种让 AI 模型安全调用外部工具和数据的标准协议，类似 API 的“万能插头”。
- Background Tasks / 后台任务：不需要用户实时等待，在服务器端异步执行的操作，比如数据处理、模型推理。
【对你有啥用】
第一，这个后台任务能力直接匹配供应链场景——比如客户提交一个排程优化请求，Agent 可以在后台跑几分钟甚至几小时，完成后推送结果，用户体验比“转圈等”好太多。第二，远程 MCP 意味着你可以让 Agent 直接连客户的 ERP 或 MES 系统，获取实时库存、订单数据来做决策，跟客户聊方案时能说“我们的 Agent 能安全接入你们现有系统”。第三，作为 PM，你可以拿这个功能去跟技术团队讨论：是否能在你们的产品里借鉴这种“托管+后台”模式，让客户不用自己部署 Agent 基础设施，降低交付成本。

Google 在 Gemini API 里推出的 Managed Agents 托管模式，本质是把 Agent 的部署、扩展、监控这些基础设施活揽过去，开发者只需写业务逻辑。这次新增的后台任务能力，意味着 Agent 可以异步执行耗时操作（比如排程计算、数据清洗），不用用户一直等响应；远程 MCP 支持则让 Agent 能通过标准协议安全调用外部系统（如 ERP、MES）。不过要注意，托管模式虽然降低了上手门槛，但在高度定制化的工业场景里，你可能还是得自己处理某些特殊的数据源适配或合规要求。

开发者社区讨论集中在两点：一是远程 MCP 的权限和认证问题（如 401/403 错误），二是后台任务的实际可靠性——有人担心长时间任务在托管环境下的重试和超时策略是否够健壮。

【详细讲给你听】
背景是市场一直在担心，AI大模型训练和部署需要大量算力，导致英伟达芯片、服务器、电力等成本暴涨，这些会不会最终传导到消费品价格上，引发新一轮通胀。沃什的观点是，短期确实有局部涨价，比如芯片价格已经涨了不少，但AI更大的作用是“降本增效”——工厂用AI优化排产、物流用AI规划路线、企业用AI替代重复劳动，这些都会压低单位成本。核心逻辑是：AI既是“需求拉动型”涨价的推手，也是“供给改善型”降价的引擎。关键细节有两个：一是沃什强调AI对生产力的提升是结构性的，不像石油危机那种纯成本冲击；二是他提到历史经验，比如互联网普及初期也推高了通信设备价格，但最终让整个经济更便宜。影响上，这给各国央行和投资者吃了颗定心丸——不用过度反应，AI可能不是通胀的敌人，而是盟友。

- 沃什 / Kevin Warsh：前美联储理事，常在财经媒体评论宏观经济政策。
- 价格效应 / Price Effect：指某项技术或政策对商品价格产生的实际影响。
- 结构性通胀 / Structural Inflation：由经济基本面变化（如劳动力短缺）导致的长期涨价，而非短期波动。
