【一句话讲清楚它在说啥】
一个开源工具，让AI编程助手（如Claude Code、Cursor）能记住你之前项目的架构、代码偏好和修复过的bug，下次会话不用重复解释。
【详细讲给你听】
背景是现在AI编程助手越来越强，但每次新开一个会话，它就像失忆一样，你得重新告诉它项目用了什么库、代码结构怎么组织、你习惯怎么写测试。内置的记忆方案（比如CLAUDE.md、.cursorrules）最多只能写200行，而且不会自动更新。这个叫agentmemory的工具解决了这个问题。核心是它通过12个钩子自动捕获你在编码时的行为，把上下文压缩成可搜索的记忆，用置信度评分、生命周期管理、知识图谱和混合搜索（BM25+向量+图）来组织。关键数据：在ICLR 2025的LongMemEval-S基准测试上，它的检索召回率R@5达到95.2%，远高于纯BM25的86.2%。成本方面，传统粘贴全部上下文每年要消耗1950万token且超出窗口限制，LLM摘要方案约65万token花500美元，而agentmemory只用17万token花10美元，如果用本地嵌入模型甚至零成本。它支持所有主流AI编程代理，包括Claude Code、Cursor、Gemini CLI、Codex CLI等，所有代理共享同一个记忆服务器。简单说，你第一次配置JWT认证，第二次问限流策略时，代理已经知道你的认证用了jose中间件、测试覆盖了token验证、选择jose是为了Edge兼容性——不用重复解释。
【关键术语小词典】
- MCP / Model Context Protocol：模型上下文协议，让AI代理和外部工具/数据源通信的标准接口
- R@5 / Recall at 5：前5个检索结果中包含正确答案的比例，衡量记忆检索质量
- BM25：经典文本检索算法，基于词频和文档长度计算相关性
- LongMemEval-S：ICLR 2025提出的长时记忆评估基准，含500个问答对
【对你有啥用】
1. 直接对标你做的决策智能平台：工业软件中，客户每次排产、优化供应链时，AI模型也需要记住历史约束、客户偏好和已解决的冲突。这个“跨会话持久记忆”的思路可以搬到你的排程算法里——比如客户第一次设定了电池产线的设备切换规则，第二次优化时模型自动记住，不用重新配置规则。
2. 产品沟通利器：下次和制造业客户（比如电池厂）聊AI落地时，可以拿这个例子说明“为什么AI需要记忆”。客户最烦的就是每次都要重复说自己的工艺参数和业务规则，agentmemory这种“零手动、自动捕获”的方案，能直接解决他们的痛点。
3. 学习路径启发：你今年想深化AI Agent/LLM应用理解，这个项目的技术栈（知识图谱+混合搜索+置信度评分+生命周期管理）是当前Agent记忆领域的前沿实践。可以把它作为案例，研究如何将类似机制应用到你的决策智能平台的产品设计中。

【详细讲给你听】
背景是现在做 Agent 的模型都太大了，跑在手机上体验很差。Cactus 团队发现一个关键洞察：工具调用本质上不是推理，而是检索加组装。模型只需要把用户的问题匹配到正确的工具名称，提取参数值，然后输出 JSON。这跟写诗、写代码不一样，不需要深度推理。所以他们做了一个极端实验：把模型里所有 MLP（前馈网络）层全部砍掉，只保留注意力机制和门控，搞出一个 26M 参数的模型 Needle。训练用了 2000 亿 token 的预训练和 20 亿 token 的合成工具调用数据，合成数据是通过 Gemini 生成的，覆盖了 15 种工具类别。结果很亮眼：在单次工具调用任务上，Needle 打败了 FunctionGemma-270M、Qwen-0.6B 这些大得多的模型。推理速度在消费级设备上达到 6000 tok/s 预填充和 1200 tok/s 解码。团队还发现，这个“不需要 MLP”的发现其实可以推广到任何模型能访问外部结构化知识的任务，比如 RAG 和检索增强生成。如果事实都在输入里，模型不需要在权重里死记硬背。不过要注意，Needle 目前只擅长单次工具调用，在多轮对话场景下不如那些大模型。
【关键术语小词典】
- Tool Calling / 工具调用：让模型识别用户意图并调用外部 API 或函数的能力，比如“查天气”触发天气 API。

- Cross-Attention / 交叉注意力：一种让模型关注输入中不同部分关系的机制，作者认为这是工具调用的核心原语。
