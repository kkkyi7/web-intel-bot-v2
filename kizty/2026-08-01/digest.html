【一句话讲清楚它在说啥】
这是一个开源 AI 技能，让 Claude 等智能体同时搜索 Reddit、X、YouTube 等平台，按真实互动数据排序，生成一份过去 30 天的综合简报，帮你快速了解某人或某话题的最新动态。
【详细讲给你听】
背景是现在信息太分散了。Google 搜不到 Reddit 评论和 X 帖子，ChatGPT 有 Reddit 但没 X，Gemini 有 YouTube 但没 Reddit，每个平台都是围墙花园。作者 mvanhorn 发现靠传统搜索根本跟不上 AI 圈的节奏，社区里讨论的新东西往往比训练数据早好几个月。核心是他做了一个叫 last30days 的技能，让 AI 代理并行搜索 Reddit、X、YouTube、Hacker News、Polymarket 等平台，用点赞数、转发量、甚至真金白银的赌注赔率来给内容排序，最后让 AI 当裁判，把散落的信息合成一份简报。关键细节有三个。第一，零配置就能用，Reddit、HN、Polymarket 和 GitHub 直接跑，跑一次后 30 秒解锁 X、YouTube、TikTok 等更多源。第二，它把不同平台的互动数据放在一起比较，比如 Reddit 的 upvote、X 的 like、Polymarket 的赔率，这些是几百万人用注意力和钱包投票的结果。第三，作者举了个例子，你要见一个人，Google 只能给你 2023 年的 LinkedIn，但 last30days 能告诉你他这月加入了 OpenAI、在跟 Anthropic 的封禁政策较劲、提交了 23 个 PR、还有 Reddit 上 569 个 upvote 在争论他是不是个讨厌鬼。机制上不是造一个更好的搜索引擎，而是用 AI 代理把十几个孤岛平台桥接起来，让你自己的 API key 和浏览器会话成为通行证。影响是，对做产品的人来说，这可能是做客户背调、竞品分析、趋势判断的新范式。
【关键术语小词典】

Walled Garden：围墙花园，指封闭生态，数据不对外开放，如 X、Reddit 各自的 API 限制。
Claude Code：Anthropic 出的命令行编程工具，支持安装第三方技能扩展。
【对你有啥用】
第一，你给制造业客户做供应链优化方案前，可以用这个技能快速摸清客户近况。比如搜客户公司名加 CEO 名字，看他们最近在 Reddit 和 X 上被怎么讨论，有没有供应商抱怨、产能问题曝光，这些信息比销售给的简报真实得多，直接提升你下次客户沟通的深度。第二，这个思路可以搬到你的决策智能平台里。你做的排程算法本质是帮客户在约束条件下找最优解，而 last30days 是帮用户在信息碎片里找最优解，它用互动数据当权重排序的方法，可以启发你在产品里加一个"社区信号"维度，比如把客户工厂的实时舆情纳入排产优先级。第三，对你学 AI Agent 和开发者工具是现成案例，这个项目的 SKILL.md 文件就是 Agent Skill 的规范写法，你可以直接扒下来看它怎么定义命令、怎么处理多平台认证、怎么设计 setup wizard，这些模式能直接用在你们平台接入 LLM 功能时参考。

【背景知识】
这个技能解决的是信息获取的碎片化问题：传统搜索引擎和单一 AI 助手都覆盖不全所有平台，而 Reddit、X、YouTube 等各自封闭，导致你想快速了解一个人或话题的最新动态时，得手动切换多个平台，效率很低。last30days 的思路不是再造一个搜索引擎，而是让 AI 代理并行去这些平台抓数据，用互动量（点赞、转发、甚至 Polymarket 的赔率）做排序，再合成一份简报。注意它的局限：依赖各平台 API 的可用性和稳定性，而且互动量高不代表内容质量高，可能被标题党或争议话题带偏。

Beacon: Knowing When and How to Perform Agentic Visual Reasoning
arXiv · Qixun Wang, Yang Shi, Letian Cheng, Zhuoran Zhang, Yan He, Yuqi Tang, Qi Zhang, Xinlei Yu, Ruizhe Chen, Tianrun Xu, Yuanxing Zhang, Pengfei Wan, Haotian Wang, Xianghua Ying · 2 天前

【一句话讲清楚它在说啥】
这篇论文发现多模态大模型用工具时，该用的时候不用、不该用的时候乱用，导致性能反而下降。他们提出Beacon模型，通过强化学习让模型学会判断何时该调用工具，整体效果明显提升。
【详细讲给你听】
这篇来自arXiv的论文，核心是在解决一个特别实际的问题：多模态大模型在复杂任务里，到底该不该调用外部工具。以前的做法是，模型一遇到难题就堆工具，结果简单问题也被拖慢，复杂问题也没真正解决。作者提出两个关键维度，一个是模式适应性，就是模型能不能判断什么时候真需要工具，另一个是工具效果，就是用了工具到底有没有带来实际收益。他们做了大量实验，发现现有模型在这两方面都表现不佳，工具带来的增益被简单问题上的失误抵消了。于是他们做了个新模型叫Beacon，核心是两个机制，一个叫必要性感知自适应奖励，鼓励模型只在必要时调用工具，另一个叫提示引导能力扩展，专门强化模型在难题上的工具使用能力。实验结果很亮眼，Beacon在多个基准测试上，整体性能和工具使用效率都明显超过现有方法。说白了，就是让模型学会聪明地偷懒，该动手时才动手。
【关键术语小词典】
MLLM / 多模态大语言模型：能同时处理文字和图片的AI模型，比如GPT-4V。
Agentic Visual Reasoning / 智能体视觉推理：让AI像助手一样，通过调用工具逐步解决视觉相关任务。
Reinforcement Learning / 强化学习：通过奖励和惩罚让AI自己学会最优策略的训练方式。
Mode Adaptiveness / 模式适应性：模型判断何时需要调用工具的能力。
【对你有啥用】
第一，这个思路可以直接映射到你的决策智能平台。客户经常抱怨AI要么过度依赖算法导致计算慢，要么该用优化算法时却硬靠规则，Beacon这个"必要性感知"的思路，完全可以借鉴到排程引擎里，让系统自动判断什么时候跑精确算法、什么时候用启发式。第二，跟客户聊产品价值时，可以拿这个框架来沟通，用模式适应性和工具效果这两个维度，帮客户理解为什么AI不是越复杂越好，而是该聪明地选择复杂度。第三，你关注AI Agent方向，这篇论文的强化学习设计很有参考价值，特别是那个自适应奖励机制，对你在产品里设计Agent的行为策略有直接启发。

Gemini API Managed Agents: 3.6 Flash, hooks, and more
Google AI Blog · Mariano Cocirio · 4 天前

【一句话讲清楚它在说啥】
谷歌给 Gemini API 的托管代理加了两大能力：更快的 3.6 Flash 模型，以及一套叫 hooks 的钩子机制，让开发者能更精细地控制代理执行流程，构建更可靠的生产级 AI 应用。
【详细讲给你听】
背景是，现在各家都在卷 AI Agent，但开发者普遍头疼一个问题：模型调用简单，但要让代理稳定地跑完一个多步骤任务，比如查库存、算排程、生成订单，中间很容易出错或失控。谷歌之前推出了 Managed Agents，相当于帮你托管代理的调度和状态管理，但控制粒度还不够细。这次更新主要解决两个痛点。核心是发布了 3.6 Flash 模型，主打低延迟和高吞吐，特别适合代理这种需要频繁来回调用的场景，比之前的版本响应更快，成本也更低。另一个关键是引入了 hooks，这玩意儿就像给代理流程装上了"关卡"或"回调函数"，你可以在代理执行到特定步骤时插入自己的代码，比如在调用外部工具前先做数据校验，或者在模型输出后做格式修正。这样开发者不用再靠提示词硬控模型，而是用代码逻辑来保证行为边界。值得注意的细节是，hooks 支持同步和异步两种模式，异步模式可以跑长时间任务，比如等一个外部审批；另外 3.6 Flash 在工具调用准确率上有明显提升，这对供应链场景里频繁调 API 的代理特别关键。影响就是，以前做 Agent 像开手动挡，现在有点像换成了自动挡但还给你留了手动干预的拨片，生产级落地的门槛降了一截。
【关键术语小词典】
Managed Agents / 托管代理：谷歌帮你管理代理运行状态和调度的服务，不用自己搭基础设施。
Hooks / 钩子：在代理执行流程中插入自定义代码的机制，用于拦截、校验或修改行为。
3.6 Flash / 3.6 闪电版：Gemini 系列的低延迟模型，主打快速响应和成本优化。
Tool Calling / 工具调用：让模型调用外部 API 或函数的能力，是 Agent 的核心基础。
【对你有啥用】
第一，你做的决策智能平台，核心是排程和优化算法，如果客户想用 Agent 来自动化处理异常订单或动态调整排产，这套 hooks 机制能让你在代理调用你的排程 API 前加一层业务规则校验，比如检查物料库存是否足够，这比纯靠模型判断靠谱得多。第二，3.6 Flash 的低延迟特性，意味着你可以把代理用在实时决策场景，比如产线异常时快速给出调整建议，这对制造业客户是很有说服力的卖点。第三，建议你在 Cursor 或 Claude 里用类似思路搭一个带钩子的原型，模拟一个"订单变更 → 触发排程重算 → 返回新计划"的流程，体验一下控制粒度，下次跟客户聊方案时能直接演示。
