【一句话讲清楚它在说啥】
一个叫 Multica 的开源项目，把 Andrej Karpathy 吐槽 LLM 写代码的常见毛病整理成一份 CLAUDE.md 文件，让 Claude Code 在编码时遵循四条原则，减少乱猜、过度设计和乱改代码的问题。
【详细讲给你听】
背景是 Andrej Karpathy 之前发帖吐槽 LLM 写代码的三大通病：第一，模型会替你瞎猜假设，不核实就直接跑偏。第二，特别喜欢把代码搞复杂，100 行能解决的问题非要写 1000 行，塞满抽象层和死代码。第三，改代码时顺手改掉不相干的注释或逻辑，产生副作用。这个项目直接把这三点转化成四条可执行的编码原则，写成一个 CLAUDE.md 文件，让 Claude Code 在每次生成代码前自动加载。核心细节：原则一是“先思考再编码”，要求模型显式列出假设、承认模糊点、主动提出更优方案。原则二是“简洁优先”，禁止添加任何没被要求的特性、抽象或配置，200 行能砍到 50 行就砍。原则三是“手术式修改”，只动你该动的代码，不顺手“优化”旁边的代码或注释，发现死代码只能提不能删。原则四是“目标驱动执行”，把模糊任务转成可验证的目标，比如“修复 bug”变成“先写一个复现 bug 的测试，再让它通过”。这个文件可以直接集成到 Claude Code 的插件里，或者手动复制到项目根目录。
【关键术语小词典】
CLAUDE.md：Claude Code 项目根目录下的配置文件，用来定义编码风格和行为规则。Andrej Karpathy：前 OpenAI 研究员、特斯拉 AI 总监，以对 AI 系统底层原理的深刻洞察著称。Multica：一个开源平台，用于运行和管理可复用的编码 agent 技能。
【对你有啥用】
第一，你正在做决策智能平台，LLM 写代码的“瞎猜假设”问题跟 AI 做排产决策时“不检查约束就输出”一模一样。下次跟客户（电池厂、药厂）聊排程算法时，可以直接引用 Karpathy 的观察：AI 需要显式列出假设、主动提问，而不是闷头跑出一个不可解释的方案。第二，这个 CLAUDE.md 文件本身就是一份“产品需求文档”的范本——它把模糊的编码行为问题拆解成四条可执行的原则，每条都有“测试标准”。你完全可以借鉴这种结构，把你负责的供应链优化产品里的“决策规则”写成类似的清晰指南，让算法 agent 在每次决策前自动加载。第三，作为想深入 AI Agent 方向的 PM，这个项目展示了“如何通过一个配置文件控制 agent 行为”，比调 prompt 更工程化。你可以在自己的 Cursor 或 Claude Code 里直接试用这个文件，体验“约束即产品”的思路。

【详细讲给你听】
背景是微软之前在一些产品里集成了Claude，比如Copilot的部分场景和内部工具，用来补充OpenAI模型的不足。但现在微软开始大规模撤掉Claude，转向自研模型和GPT-4o。核心原因是成本：Claude按token收费，对微软这种体量的调用量来说，账单非常吓人。但更关键的是战略——微软不想把核心AI能力绑在第三方身上，尤其是Anthropic背后还有谷歌投资。关键细节有两个：一是微软内部评估发现，自家的小模型在某些任务上已经能接近Claude 3.5 Sonnet的效果，成本却低一个数量级；二是微软正在推动“模型路由”架构，根据任务自动选择最便宜的模型，Claude在这种体系里成了最容易被替换的那个。影响上，这对Anthropic是个坏消息，失去微软这个渠道意味着收入缺口和品牌曝光下降。对行业来说，这说明大厂正在加速“去第三方化”，未来AI模型市场会越来越像云服务——自研为主，外部采购只做补充。
【关键术语小词典】
- 模型路由：根据任务类型自动选择最合适的AI模型，目的是平衡成本和效果。
- Anthropic：开发Claude模型的AI公司，主要投资者是谷歌。
- Copilot：微软推出的AI助手产品，集成在Office、GitHub等工具中。
【对你有啥用】
第一，你在做决策智能平台，这个“模型路由”的思路可以直接用到你的产品里。比如给客户做排产优化时，不同场景（简单规则 vs 复杂约束）可以用不同模型，既能降本又能提效，下次跟客户聊方案时可以把这个当卖点。第二，微软弃用Claude说明企业级AI采购正在从“谁强用谁”转向“谁可控用谁”，你给制造业客户推AI产品时，要强调你的平台不是绑死某个模型，而是支持灵活切换，这正好击中客户对供应商锁定的焦虑。第三，你今年想深化AI Agent理解，这个案例是个很好的学习素材——微软的决策逻辑（成本+控制权）就是产品经理做技术选型时该有的思维框架，建议你拆解一遍，写进你的学习笔记里。

【一句话讲清楚它在说啥】
UniPat AI 搞了个叫 SaaS-Bench 的测试，让 Claude 等大模型去干真实的办公软件操作，结果最高通过率才 3.8%，说明 AI 想完全替代人自动办公还差得远。
【详细讲给你听】
背景是之前很多 AI 产品，比如 Claude 的 Computer-Use 功能，演示时看起来很牛，能自己操作电脑、点按钮、填表格，给人一种“全自动办公马上来了”的错觉。但 UniPat AI 团队觉得这些演示太“表演性质”，于是搞了个更严格的评测基准 SaaS-Bench。核心是让模型在真实 SaaS 软件里完成 100 多个典型办公任务，比如在 CRM 里更新客户信息、在表格里做数据透视、在项目管理工具里排任务。结果很残酷：表现最好的模型（Claude 3.5 Sonnet）完全通过率只有 3.8%，其他模型更惨。关键细节是，模型在简单步骤上还行，但一旦遇到多步骤、需要上下文理解、或者界面有微小变化（比如弹窗、按钮位置偏移），就立刻崩了。影响是，这撕碎了“AI 全自动办公”的幻想，说明当前大模型在复杂、动态的软件操作上还非常脆弱，开发者不能盲目相信演示视频，得对落地场景有清醒预期。
【关键术语小词典】
- SaaS-Bench：一个专门测试 AI 在真实办公软件中完成任务能力的评测基准。
- Computer-Use：Claude 的一项功能，让 AI 能像人一样操作电脑屏幕上的软件。
