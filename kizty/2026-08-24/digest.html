【一句话讲清楚它在说啥】
一个开源工具，把几十家 AI 模型提供商的免费额度聚合到一个入口，让你在终端、IDE 或手机里免费用 Claude Code、Codex 等编程助手，每月能薅 13 亿 token 的羊毛。
【详细讲给你听】
这工具叫 FCC，全称 Free Claude Code，是个独立开源项目，跟 Anthropic 官方没关系。背景是现在各家大模型厂商为了抢用户，都给了免费额度，但分散在不同平台，用起来麻烦，而且直接拿免费 key 跑 Claude Code 这类编程助手，容易触发风控封号。FCC 的思路是当个中间层，把 49 家合规的模型提供商聚合起来，你只需要配一次，它自动帮你路由到有免费额度的模型，用完一家自动切下一家，不用手动换 key。核心亮点有三个。第一，每月能薅 13 亿 token，覆盖 Claude、Codex、Grok 这些主流模型，还支持本地模型。第二，它做了输出优化，能砍掉最多 90% 的终端输出 token，省着用免费额度。第三，支持语音输入，用本地 Whisper 转文字，然后直接跟编程助手对话。对开发者来说，这意味着不用再纠结订阅哪家，一个工具全搞定，而且断了服务会自动切换，不打断思路。这项目本质是薅羊毛的工程化，但背后反映的是模型提供商之间价格战和免费策略的激烈竞争。
【关键术语小词典】
FCC：Free Claude Code 缩写，一个聚合多家 AI 模型免费额度的开源工具。
ToS-friendly：Terms of Service friendly，指遵守服务条款、不违规的使用方式。
RTK：Reduced Token 模式，通过过滤常见命令输出来减少 token 消耗的功能。
NVIDIA NIM：英伟达的模型推理服务，这里用作语音转文字的转录引擎。
【对你有啥用】
第一，你平时做产品原型或者写技术方案，经常要试不同模型的输出效果。这工具让你在一个界面里切换 Claude、Codex、Grok，不用分别注册充值，直接对比各家在供应链优化场景下的代码生成能力，省下的时间够你多写两页 PRD。第二，你关注 AI Agent 落地，FCC 这种聚合层思路可以借鉴到决策智能平台里。客户现场经常有数据孤岛和多个系统并存的问题，FCC 的路由和自动切换机制，本质上是个模型网关，这个架构模式可以直接讲给客户听，解释你们平台怎么统一调度不同算法引擎。第三，你研究开发者工具方向，这个项目的安装方式、配置流程和社区运营值得拆解，它靠免费额度吸引开发者，再通过插件生态锁定用户，这个增长飞轮对做企业级产品也有参考价值。

【详细讲给你听】
背景是，现在大模型写代码、写文档已经很溜了，但真正要理解一篇科研论文，把里面的实验步骤、数据、方法一步步跑通并复现结果，这需要极强的推理和工具调用能力，之前没人做到过。Inherent 这家公司，创始人全是 DeepMind 出来的，他们觉得 AI 不应该只做聊天和写作，应该去干科研这种重活。核心是他们发布的 Faraday，一个专门为科研场景设计的 AI 智能体，能读论文、写代码、跑实验、对比结果，整个流程自动化。关键细节是，他们说在复现论文的基准测试里，Faraday 的成功率超过了 Anthropic 和 OpenAI 的旗舰模型，而且速度还更快。这意味着什么？如果 AI 能自动复现论文，那科研人员就不用花几个月去验证别人的工作，可以直接站在别人的肩膀上做创新。对工业界来说，这意味着技术验证和竞品分析的周期会被大幅压缩，你拿到一篇新论文，AI 帮你跑通，你直接评估能不能用到自己的产品里。
【关键术语小词典】
- AI agent / AI 智能体：能自主完成多步任务的 AI 程序，不只是聊天，会自己调用工具。
- DeepMind：谷歌旗下顶级 AI 研究机构，AlphaGo 就是他们做的。
- Benchmark / 基准测试：一套标准化的测试任务，用来公平比较不同 AI 模型的性能。
- Faraday：Inherent 发布的科研 AI 智能体的名字，以科学家法拉第命名。
【对你有啥用】
第一，这个思路可以直接映射到你的决策智能平台。客户最头疼的不是算法不好，而是验证算法在真实场景里的效果要花大量时间。如果 Faraday 能复现论文，那你的平台是不是也可以做一个“复现客户现有排程方案”的功能，让客户看到你的算法比他们现在用的好多少，这比任何 PPT 都有说服力。第二，这改变了你对 AI Agent 能力的认知。之前你觉得 Agent 做做工具调用、写写代码就不错了，现在它能做科研复现，说明 Agent 的推理深度已经到可以处理复杂工业场景的程度了。你可以在 Cursor 或者 Claude 里试试让 AI 帮你拆解一个供应链优化论文的步骤，看看它能不能给你一个可执行的实验方案。第三，对产品定位有启发。Faraday 是垂直场景的 Agent，不是通用聊天机器人。你做工业软件，也应该往“垂直场景 Agent”方向想，而不是做一个大而全的东西，这正好符合你今年想深化的 AI Agent 应用方向。

OmniAssistBench：全模态助手交互基准
OmniAssistBench: Assistant-style Interaction Benchmark for Omni-LLMs
arXiv · Xianyun Sun, Chaoyou Fu, Zhengye Zhang, Feiyang Duan, Qingyuan Cao, Yonghui Niu, Sihang Yuan, Ge Zhang, Caifeng Shan · 3 天前
⌄
http://arxiv.org/abs/2608.21360v1
【相关性评分】
9
【一句话讲清楚它在说啥】
新出的一个评测基准，专门测试全模态大模型能不能像真人助手一样，边看视频边引导用户完成任务。测下来 Gemini-3-Pro 得 66.4 分，开源 Qwen3 得 51.2 分，都远没到及格线，模型普遍看不懂手势、记不住多轮对话。
【详细讲给你听】
这篇 arXiv 论文解决的是一个大问题：以前测视频理解，都是给模型一段视频然后问问题，属于被动理解。但真实场景里，助手要边看实时画面边主动引导用户，比如你举着手机拍设备，让 AI 告诉你下一步拧哪个螺丝。这种交互式评估很难做，因为模型回答会改变用户下一步动作，静态数据集根本没法模拟。

作者团队搞了个叫 OmniAssistBench 的基准，核心思路是反向工程。他们从现有互联网视频里反推用户目标，把视频切成多轮片段，模拟连续交互。为了保证评测公平，还提前给模型设定好"必须走同一条路线"的先验条件，防止不同路径导致分数没法比。整个数据集花了超过 1000 个专家工时来构建。

结果挺扎心：闭源的 Gemini-3-Pro 拿 66.4 分，开源 Qwen3-Omni-Instruct 拿 51.2 分，满分 100。模型普遍能听懂用户话，但回答经常错或不全。三个典型毛病：看不懂手势这种视觉提示、多轮对话里记不住之前说过啥、该等目标事件发生时不延迟响应。说白了，现在这些模型当"视频陪聊"还行，当"任务教练"差得远。
【关键术语小词典】
Omni-LLMs：全模态大模型，能同时处理文字、图像、音频、视频的模型。
Benchmark：基准测试，用统一任务和评分标准衡量模型能力的测试集。
Reverse-engineering：反向工程，从成品反推原始设计或目标的过程。
Gemini-3-Pro：谷歌闭源旗舰多模态模型，目前交互能力领先。
【对你有啥用】
第一，你做的决策智能平台如果涉及"AI 引导用户操作"场景，比如工厂工人按 AI 指引完成排产调整，这个基准的失败案例直接告诉你产品要避开哪些坑。手势识别和多轮记忆不是加分项，是及格线。第二，你关注 AI Agent 落地，这篇论文的"反向工程构建数据集"思路可以借鉴。你们做供应链优化时，如果真实交互数据稀缺，能不能从历史工单或操作日志反推用户意图，造出训练数据。第三，跟客户聊"AI 助手"价值时，别吹全知全能，直接说"当前模型在引导式任务上只有 60 分水平"，反而显得你专业，还能顺势推你的平台做兜底方案。

【背景知识】
传统多模态评测（如视频问答）是静态的：给模型一段视频再问问题，测的是被动理解。但真实助手场景是交互式的——模型得边看实时画面边主动引导用户，且它的回答会改变用户下一步动作，静态数据集无法模拟这种动态闭环。OmniAssistBench 的思路是反向工程：从互联网视频反推用户目标，切成多轮片段模拟连续交互，并预设先验条件保证评测公平。不过这类基准有个天然局限：评测分数高度依赖任务设计和评分标准，模型在基准上的表现未必能直接迁移到真实场景的开放性和不确定性中。

什么是 Harness
What Is a Harness?

【一句话讲清楚它在说啥】
一篇讨论 AI Agent 开发中 Harness 概念的帖子，核心观点是 Harness 是连接模型与真实任务的中间层，类比为汽车的底盘或电子设备中的电路，决定了 Agent 的实际能力边界。
【详细讲给你听】
这篇 HN 热帖来自开发者 tosh 的个人博客，讨论的是 AI Agent 开发中一个正在被频繁提及但定义模糊的概念：Harness。背景是，随着 Claude、GPT 这类大模型能力趋同，大家发现模型本身不再是差异点，真正决定产品好坏的是你怎么"套"住它、怎么让它干活。作者提出一个类比：Harness 是底盘，模型是引擎，token 是燃料，Agent 是整车。评论区有人补充说，如果 LLM 是电力，Harness 就是电子设备，未来真正的价值提供者是 Harness 而不是模型本身。帖子下面有实战派分享，比如有人给会计 Agent 做了内部 CLI 工具，发现让 LLM 通过命令行交互比预设技能更灵活；也有人问 Harness 能不能解决"交接"问题，比如从终端到手机、从一个人到另一个人、从一个模型到另一个模型。还有一条评论泼冷水，说 Harness 是个被发明出来的模糊术语，真正的问题是：怎么让有限上下文的 LLM 像新人一样融入复杂代码库。整体看，这篇帖子在讨论 Agent 工程化的核心痛点：控制、编排、交接、扩展。
【关键术语小词典】
Harness：本意是马具，在 AI 领域指连接模型与实际任务的中间控制层，类似底盘或电路板。
Agent：能自主完成多步骤任务的 AI 系统，基于模型但包含工具调用、记忆、规划等能力。
CLI：命令行界面，让 Agent 通过文本指令直接操作系统和工具。
Extension：扩展系统，允许用户给 Harness 添加自定义功能模块。
【对你有啥用】
你正在做决策智能平台，这个 Harness 概念可以直接映射到你的产品架构里。你们给制造业客户做排程优化，模型负责出方案，但真正决定客户用的是不是你们平台，其实是"怎么把模型接进客户现有的 ERP、MES 系统"这个 Harness 层。下次跟客户聊，可以主动提"我们不只是给算法，我们给的是能嵌进你现有流程的 Harness"，这比讲模型多准更有说服力。另外，评论区那个"内部 CLI 比预设技能更灵活"的观点，对你设计 Agent 交互方式有直接启发。你们做供应链优化，客户场景千差万别，与其预设一堆技能模板，不如给客户一个 CLI 或脚本接口，让他们自己定义 Agent 怎么跟系统交互。这能解决你们产品在客户现场落地时"场景太定制化"的痛点。最后，那个关于"交接"的讨论值得你关注。供应链场景里，一个决策任务经常要跨系统、跨角色、跨时间流转，如果 Harness 能解决这种交接问题，那你们平台的价值会大很多。你可以去研究一下现在有没有开源 Harness 支持这种跨模态交接，说不定能成为你们产品的差异化功能。

【背景知识】
Harness 这个词在 AI Agent 开发里最近被频繁提起，但定义还很模糊。简单说，它指的是包在 LLM 外面的那层软件基础设施——负责工具调用、上下文管理、权限控制、任务编排这些模型本身不擅长的事。类比一下：模型是引擎，Harness 是底盘，Agent 是整车。现在模型能力趋同，真正拉开产品差距的往往就在这层。不过也有开发者泼冷水，认为这词是被发明出来的模糊术语，真正的难点是让上下文有限的 LLM 像新人一样融入复杂代码库，而不是纠结术语。

Can You Feel My Pain? Neural-Behavioural Changes in Caregiver-Infant Dyads During Ostracism.
PubMed · Niloofar Goharbakhsh, Louisa Kulke · 2026年
⌄
https://pubmed.ncbi.nlm.nih.gov/42633617/

【一句话讲清楚它在说啥】
研究5到7个月婴儿被游戏排斥时，妈妈和婴儿的脑电和行为反应。发现婴儿脑电有变化但妈妈没有，母婴同步不是越高越好，而是灵活调节才健康。
【详细讲给你听】
这篇研究想搞清楚一个事：当小婴儿在社交中被冷落，比如玩游戏没人传球给他，他和妈妈的大脑活动会不会同步变化。以前没人同时测过婴儿和妈妈的脑电，所以这是头一回。

实验设计很简单，婴儿和妈妈一起玩抛球游戏，有时候故意不传给婴儿，模拟被排斥的感觉。一边玩一边用脑电帽记录大脑活动，还录像分析表情和行为。

结果有三个关键发现。第一，婴儿和妈妈在被排斥时情绪反应都变强了，说明婴儿确实能感觉到被冷落。第二，只有婴儿的大脑theta波功率升高，妈妈没有，说明婴儿自己在处理这个社交信号，不是全靠妈妈。第三，母婴之间的脑同步并没有因为排斥而普遍增强，反而取决于具体情境。

最有意思的结论是，同步不是越多越好。研究者提出一个概念叫共同调节，意思是好的母婴互动不是一直保持高同步，而是能根据情境灵活切换同步和不同步。就像跳舞，不是每一步都踩在同一个拍子上，而是该合拍时合拍，该分开时分开。

这个发现对理解婴儿早期社交发展和情绪调节能力挺重要，也挑战了以前觉得同步越高越好的简单想法。
【关键术语小词典】
Ostracism：排斥。被群体故意忽略或排除在外的社交体验。
Hyperscanning：超扫描。同时记录两个人或多个人的大脑活动，看他们之间有没有同步。
Theta power：theta波功率。大脑活动的一种频率，和注意力、情绪处理有关。
Inter-brain synchrony：脑间同步。两个人大脑活动出现相似节律的现象。
【对你有啥用】
第一，你做的决策智能平台本质是帮企业在复杂环境里找最优解，这篇研究提出的灵活调节比持续同步更有效的观点，可以类比到供应链协同。你和客户聊多级供应链协同优化时，可以提一句，不是所有节点都要实时同步，有时候松耦合反而更抗风险，这个思路能帮你和客户建立认知共鸣。

第二，你关注AI Agent和LLM应用，这篇研究里婴儿和妈妈的行为同步模式，可以启发你思考人机协作的交互设计。现在很多AI助手追求时刻响应，但也许更自然的方式是像母婴互动那样，根据任务复杂度灵活切换介入程度，这个想法可以在你设计产品交互时作为参考。

第三，你今年想深化工业软件加AI的产品理解，这篇研究用脑电和行为两个维度同时测量，这种多模态数据融合的思路，和你做决策智能时融合多源数据建模是相通的。下次做产品方案时，可以强调多模态数据比单一数据更能捕捉真实状态。

【一句话讲清楚它在说啥】
这篇论文提出一个叫 ReasonCast 的框架，用 AI Agent 判断哪些事件文本值得纳入需求预测，再通过结构化字段修正预测，避免乱加文本反而搞坏预测精度。
【详细讲给你听】
背景是需求预测现在不能只看历史销量，还得考虑促销、节假日、价格变动这些未来事件。以前的做法是把文本一股脑塞进模型，不管有没有用都混进去，结果经常帮倒忙。ReasonCast 的思路是让一个 Agent 先看事件描述、无文本预测结果和不确定性，判断这次要不要用文本推理。如果要，就把事件知识转成结构化字段，包括相关性、需求方向、时间形状、幅度和峰值强度。这些字段不是随便加的，而是分别走两条路：加法路径修局部趋势和时间形状，乘法路径抓事件导致的水平跳变。训练也分三步走，先是 Schema SFT 建立字段，再用语义强化学习校准方向幅度，最后用预测效用强化学习让推理对齐边际改进。效果上，节假日敏感品类 WMAPE 降了 3.29 个百分点，大促敏感品类降 1.25，M5 事件窗口降 0.47。但稳定销售期如果乱干预，误差反而涨 1.68 个百分点，所以选择性很重要。说白了就是让 AI 学会什么时候该插嘴，什么时候闭嘴。
【关键术语小词典】
WMAPE：加权平均绝对百分比误差，预测准确度的核心指标，越低越好。
SFT：监督微调，用标注数据让模型学会特定任务的基础能力。
RL：强化学习，通过奖励信号让模型自己摸索最优策略。
M5：一个公开的零售预测竞赛数据集，常用于验证预测算法。
【对你有啥用】
第一，你做的排程算法和供应链优化，本质上也是预测加决策。ReasonCast 这种先判断要不要干预的思路，可以直接借鉴到你的产品里。比如客户工厂有临时插单或设备检修，系统可以先评估这个事件对排程的影响程度，再决定要不要重排，而不是每次都全量重算。第二，跟客户聊需求预测时，你可以拿这个案例讲清楚为什么纯堆数据不行，关键在结构化事件建模和选择性推理。这比讲一堆算法细节更能让制造业客户听懂价值。第三，你关注 AI Agent 落地，这篇展示了 Agent 在预测场景的具体工作方式，不是聊天机器人那种泛化对话，而是带着明确决策目标的推理。下次你在内部讨论 Agent 产品边界时，可以拿这个做参照。

这篇论文解决的是零售业一个很实际的问题：货架上某个商品缺货了，顾客本来想买它，现在会去买什么替代品。传统做法是给每个可能的商品组合都建一个选择模型，然后逐一预测需求，这在商品数量少的时候还行，但一旦商品库有几百万个SKU，组合爆炸，根本算不过来。作者提出一个更聪明的思路：先独立预测每个商品的需求，然后加一个“需求转移系数”来修正，这个系数代表目标商品缺货时，它的需求有多大比例会转移到其他商品上。核心难点在于怎么高效估算这个系数，作者用了受限逻辑模型，在几百万商品的规模上也能算得动。实验用的是多个地点的历史交易数据，结果显示只要替代行为符合一些合理假设，这个方法的估算精度很高，能明显改善需求预测。关键细节有三个：一是DT系数本质上是百分比，表示需求流向；二是方法在百万级商品库上可运行；三是实验验证了在合理假设下，估算结果准确且能提升预测效果。对供应链和零售行业来说，这意味着不用再为每个商品组合单独建模，省下的计算成本是数量级的。

这篇论文用图神经网络指导遗传算法，解决实物互联网里工厂、仓库、零售商三级网络的分配和补货问题，在成本不确定时比传统算法更稳更快，还做了消融实验验证效果。
【详细讲给你听】
背景是实物互联网这个概念，它把传统供应链里的仓库、工厂、零售商连成一个协作网络，允许横向调货，而不是各管各的。这样一来，决策就变得特别复杂，既要决定哪个工厂给哪个仓库供货，又要算连续物流量，还得面对成本波动。以前的方法要么用精确算法硬算，要么用遗传算法瞎试，但都慢或者不稳。

这篇论文的核心做法是把图神经网络和遗传算法结合起来。先用GNN学习每个工厂被选中的概率，用这个概率去初始化遗传算法的第一代种群，而不是随机生成。然后，在进化过程中，根据预测的不确定性调整变异操作，让算法更聪明地探索。每个新方案都要解一个线性规划来算真实成本，保证评估靠谱。

关键细节有几个。第一，在400次评估的严格预算下，GNN-GA在10次匹配运行里全部赢过传统GA。第二，消融实验显示，学习到的初始化贡献了大部分提升，而熵引导变异的效果则因实例而异。第三，他们用了15个实例测试，还专门做了迁移测试，看模型在新场景下是否管用。整体思路就是，把机器学习当向导，让传统算法少走弯路。
【关键术语小词典】
Physical Internet / 实物互联网：把供应链节点像互联网数据包一样互联，实现资源共享和动态调配。
GNN / 图神经网络：专门处理图结构数据的深度学习模型，这里用来预测工厂选择概率。
Min-max regret / 最小最大后悔值：一种在不确定条件下做决策的稳健优化方法，追求最坏情况下损失最小。
Genetic Algorithm / 遗传算法：模拟自然选择的进化算法，通过选择、交叉、变异迭代找最优解。
【对你有啥用】
这篇对你的价值很直接。第一，你做的排程算法和决策智能平台，本质上也是组合优化加连续流问题，GNN引导初始化的思路完全可以借鉴到你自己的优化引擎里，比如用图网络预测初始排程方案，减少冷启动的试错成本。第二，跟制造业客户聊的时候，他们最怕的就是成本波动导致计划失效，你可以拿这个min-max regret框架当案例，讲你们平台怎么帮他们在不确定环境下做稳健决策，这比单纯说算法快更有说服力。第三，你关注AI Agent和工具产品，这种ML加传统算法的混合架构，其实也是Agent工具链里做规划模块的一个可行范式，值得在技术选型时留意。

On the global feature importance for interpretable and trustworthy heat demand forecasting

【相关性评分】

【一句话讲清楚它在说啥】
这篇论文提出一种在模型训练前就能评估特征重要性的方法，用于区域供热系统的热需求预测，让机器学习模型的判断依据更透明、更可信，方便向监管和客户解释。
【详细讲给你听】
背景是区域供热系统现在越来越多用机器学习来预测热需求，好提前调度能源。但问题来了，模型像个黑盒子，它凭什么这么预测，没人说得清。这在涉及公共事业、要面对监管审查和客户投诉时，就很麻烦。以前常用的解释方法像排列特征重要性，会把数据随机打乱，产生一些现实中根本不会出现的假数据，反而误导判断。这篇论文的解法是换一套思路，用四种不依赖随机扰动的办法来交叉验证。其中梯度提升本身自带特征重要性，属于事前解释，另外三种是事后分析，包括部分依赖图、累积局部效应和SHAP。关键是这些方法都不需要打乱数据，避免了人为制造不合理样本的偏差。作者在真实供热场景里对比了这些方法的结果，看它们哪些结论一致，哪些能互补，最后给出了一套怎么结合使用、怎么向非技术方解释的建议。说白了，就是给黑盒模型装一个靠谱的仪表盘，让决策者敢用、客户能信。
【关键术语小词典】
ante-hoc Explainable AI：事前可解释人工智能，指模型本身设计时就自带可解释性，而非事后分析。
SHAP：沙普利加性解释，一种博弈论启发的特征归因方法，量化每个特征对预测的贡献。
Partial Dependence：部分依赖图，展示单个特征变化时预测结果的平均变化趋势。
Accumulated Local Effects：累积局部效应，类似部分依赖但能处理特征相关性问题。
【对你有啥用】
第一，你做的决策智能平台如果涉及预测类模块，比如排程算法里的需求预测，这套不依赖随机扰动的解释思路可以直接借鉴，尤其面对电池或医药客户时，他们审计要求高，这套方法能帮你把模型依据讲清楚。第二，下次跟客户聊AI落地，可以主动提这个案例，说明你们平台在可解释性上不是事后补丁，而是从建模阶段就考虑，这会比单纯强调精度更有说服力。第三，这篇论文对比了多种解释方法的一致性和互补性，你可以在产品里设计一个解释报告模块，自动输出多维度特征重要性，让客户自己交叉验证，降低信任门槛。
