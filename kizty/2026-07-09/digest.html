【详细讲给你听】
背景：以前我们只知道 AI 模型能回答问题，但不知道它被“教”了哪些规则——比如 Claude 被要求“不要承认自己是 AI”，ChatGPT 被要求“先思考再回答”。这些规则藏在 system prompt 里，通常只有模型厂商内部知道。核心：这个 GitHub 仓库（asgeirtj/system_prompts_leaks）把 Anthropic、OpenAI、Google、xAI 等主流厂商的 system prompt 都扒了出来，并且持续更新。关键细节：1）它收录了 Claude Fable 5、Opus 4.8、GPT-5.5 Thinking、Gemini 3.5 Flash 等最新模型的完整 system prompt。2）还提供了版本对比（Diff），比如 Claude Opus 4.8 升级到 Fable 5 时，system prompt 改了哪些地方。3）连 Claude Design（带 48 个工具、16 个技能）、GitHub Copilot for macOS 这种细分产品的 prompt 都有。影响：对开发者来说，这相当于拿到了 AI 产品的“源代码说明书”——你可以直接看到模型被设定成什么性格、有什么限制、如何调用工具。对产品经理来说，这是研究竞品行为逻辑的第一手资料。
【关键术语小词典】
- System Prompt / 系统提示词：AI 模型启动时内置的指令，定义它的角色、行为规则、工具使用方式等。
- Diff / 差异对比：显示两个版本之间具体改了哪些内容，方便追踪变化。
- Claude Fable 5 / Opus 4.8：Anthropic 发布的不同版本 Claude 模型，Fable 5 是最新版，Opus 4.8 是上一代旗舰。

【一句话讲清楚它在说啥】
Bun 的创始人用 AI Agent 在 11 天内把核心代码从 Zig 重写成了 Rust，花了 16.5 万美元的 API 费用，最终用户几乎没感觉到变化，但内部 bug 大幅减少。
【详细讲给你听】
背景是 Bun 这个 JavaScript 运行时一开始是用 Zig 写的，性能很好但内存管理问题导致大量崩溃。创始人 Jarred 说“我厌倦了睡觉时担心 crash”。传统上，大型软件重写是禁忌，因为 Joel Spolsky 早在 2000 年就警告过“永远不要从头重写”。但这次不一样。核心是 Anthropic 的 Claude Agent 配合了一个关键策略：Bun 的测试套件是用 TypeScript 写的，语言无关，所以可以当作“一致性测试”来验证新代码是否正确。Agent 花了 11 天，消耗了 59 亿个输入 token 和 6.9 亿个输出 token，API 成本约 16.5 万美元。Jarred 的做法是让 Agent 先自动迁移，然后人工监控工作流，发现问题就修改 Agent 的生成逻辑，而不是手动改代码。最终结果：新 Rust 版本在 Claude Code 里跑了近一个月，启动快了 10%，但“无聊”到几乎没人注意到变化。Jarred 强调，真正改变游戏规则的是“语言无关的测试套件”和“对抗性代码审查”这套流程，而不是 AI 本身。
【关键术语小词典】
- Bun / 邦：一个 JavaScript 运行时，类似 Node.js 但更快，最初用 Zig 语言开发。
- Zig / 齐格：一种系统编程语言，强调手动内存管理，性能接近 C。
- RAII / 资源获取即初始化：Rust 的一种自动内存清理机制，能防止忘记释放内存的 bug。
- Conformance Suite / 一致性测试套件：一套独立于编程语言的测试用例，用来验证实现是否符合规范。
【对你有啥用】
1. 产品判断：这个案例直接颠覆了“永远不要重写”的行业铁律。你在做决策智能平台时，如果遇到遗留代码或算法模块需要重构，可以思考“我们的测试套件是否足够语言无关”。如果测试是业务逻辑驱动的（比如排产算法的输入输出校验），那 AI Agent 重写就变得可行。下次跟客户聊技术债务时，可以提这个案例作为“AI 辅助重构”的论据。
2. 客户沟通：你们服务的制造业客户（电池、钢铁）往往有老旧的排程系统。你可以用这个故事说明：AI 不是只能做预测，还能帮他们安全地现代化遗留系统。关键话术是“我们不需要从头造轮子，只需要一个足够好的测试集，AI 就能帮你把旧代码翻译成新架构”。
3. 学习路径：你今年想深化 AI Agent 和 LLM 应用的理解。这个案例展示了“Agent 工程”的完整工作流：动态工作流、试运行、对抗性审查、修复生成逻辑而非修复代码。你可以把这种“过程驱动”的思路应用到你的产品中——比如让 Agent 自动生成排产方案的候选，然后用历史数据做一致性校验。

【详细讲给你听】
背景是现在做数据分析时，数据都锁在数据库里，必须通过JDBC或ODBC这些驱动去读。这些驱动是为事务查询设计的，不是为批量列式分析优化的，所以成了瓶颈。核心创新是Jailbreak方法：它让LLM直接读取数据库的存储文件（比如PostgreSQL和MySQL的底层文件），跳过数据库引擎，把数据直接转成Apache Arrow格式的内存列式缓存。关键细节有三：第一，LLM靠读取数据库文件格式的源码和文档来生成读取代码，不需要人工写解析逻辑。第二，生成的Arrow缓冲区可以被DuckDB、Spark、cuDF等主流引擎直接消费。第三，在TPC-H基准测试上，端到端分析吞吐量最高提升了27倍。影响很直接：这意味着数据不再被特定数据库锁定，你可以用任意引擎分析任意数据库的存储文件，对离线分析、只读副本、数据迁移场景是颠覆性的。
【关键术语小词典】
Apache Arrow：一种跨语言的内存列式数据格式，让不同系统间零拷贝共享数据。TPC-H：数据库性能测试的行业标准基准，模拟决策支持系统查询。JDBC/ODBC：数据库连接的标准接口，传统上所有数据读取必须经过它们。

【详细讲给你听】
背景是，过去十年云基础设施（比如Kubernetes）都是假设使用者是“人”——人能读文档、能理解YAML报错、能看监控面板自己找问题。虽然对开发者来说很痛苦，但人脑能补上缺失的上下文。现在Agent来了，它们没有这个能力。Modal的CTO Akshat Bubna在播客里说，Agent需要的是“能写代码、运行、看输出、改环境、调试失败、再试一次”的闭环，而且这个循环要极快。关键细节有三点：第一，Modal现在支持Agent自己弹起沙箱（sandbox），一个强化学习训练任务可能需要10万个沙箱同时跑；第二，他们提出了“从开发者体验到Agent体验”的转变，意味着基础设施要变成可编程的，Agent能直接调用API来部署、监控、回滚；第三，Modal的GPU快照和弹性推理能力，专门应对AI工作负载的突发性——传统云是按“稳定流量”设计的，但Agent的推理请求像脉冲一样忽高忽低。影响是，这重新定义了“云”该长什么样：不再是给人类看的控制台，而是给Agent用的API和沙箱环境。对于做AI产品的团队，这意味着选型时不能只看“开发者友好”，还要看“Agent友好”。
【关键术语小词典】
- Sandbox / 沙箱：一个隔离的、可快速创建和销毁的运行环境，Agent可以在里面安全地跑代码、做实验。
- GPU Snapshotting / GPU快照：把GPU当前的计算状态完整保存下来，下次直接恢复，避免重新加载模型，大幅减少冷启动时间。
- Elastic Inference / 弹性推理：根据请求量自动伸缩推理计算资源，高峰期加机器，低谷期释放，节省成本。
- Supercloud / 超级云：跨多个云厂商（Modal接了17家）统一调度资源，避免被单一云绑定。
【对你有啥用】
1. 你正在做决策智能平台，客户是制造业。如果未来Agent要自动调排产算法、自动跑仿真，你的平台底层架构就得支持“Agent可编程”——比如让Agent通过API直接创建沙箱跑优化模型，而不是让人去点界面。这直接影响到你平台的产品架构设计。
