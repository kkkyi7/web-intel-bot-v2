【详细讲给你听】
背景：之前大家用 AI 模型，只能看到输入输出，不知道模型背后被设定了什么“潜规则”。比如 Claude 是不是被要求更“谨慎”？GPT 是不是被要求更“直接”？这些底层指令（System Prompt）一直藏在黑箱里。
核心：这个 GitHub 仓库（asgeirtj/system_prompts_leaks）把 Anthropic、OpenAI、Google、xAI 等公司最新模型的系统提示词全扒了出来，并且做了版本对比（Diff）。比如 Claude Opus 4.8 升级到 Fable 5 时，系统提示词里哪些句子被删了、哪些被加了，一目了然。
关键细节：仓库里包含了 Claude Fable 5、Opus 4.8、Sonnet 5 的完整提示词，以及 GPT-5.5 Thinking、Instant、Codex 的提示词。还收录了 GitHub Copilot、VS Code Copilot Agent、Perplexity Computer 等工具的提示词。最实用的是“Diff”功能，能直接看到两个版本之间的差异。
机制或影响：这相当于把 AI 模型的“出厂设置”和“行为准则”公开了。对开发者来说，你能知道为什么同一个问题，Claude 和 GPT 回答风格不一样——因为背后指令不同。对产品经理来说，这能帮你理解大厂是如何通过提示词工程来“调教”模型的，比如让模型更安全、更创意、或更工具化。
【关键术语小词典】
- System Prompt / 系统提示词：AI 模型启动时被设定的底层行为规则，决定模型如何回答、遵守什么限制。
- Diff / 差异对比：显示两个版本之间具体哪些内容被修改、添加或删除。
- Claude Fable 5 / Opus 4.8：Anthropic 的不同模型版本，Fable 5 是最新创意型模型，Opus 4.8 是上一代高性能模型。
【对你有啥用】
1. 产品设计参考：你可以直接看 Claude 和 GPT 的 System Prompt 是如何设计“角色”和“约束”的。比如 Claude 的提示词里如何定义“助手”的边界，GPT 的“Thinking”模式如何引导推理。这能直接帮你优化自己产品的 AI 交互设计。

【一句话讲清楚它在说啥】
Bun 的创始人 Jarred 用 11 天、花了 16.5 万美元的 API 费用，借助 AI Agent 把 Bun 的核心从 Zig 重写成了 Rust，并且上线后用户几乎没察觉变化。
【详细讲给你听】
背景是 Bun 这个 JavaScript 运行时一开始是用 Zig 写的，性能很好，但内存管理问题导致大量 use-after-free、double-free 这类 bug，让 Jarred 晚上睡不着觉。过去没人敢对大型项目做“停世界重写”，因为 Joel Spolsky 二十年前就说过这是大忌。但这次不一样了。核心是 Jarred 利用 Anthropic 内部的 Mythos/Fable 模型（Claude 的进阶版），配合一套精心设计的 Agent 工作流：动态工作流、试运行、对抗性代码审查。关键细节有三：第一，Bun 的测试套件是用 TypeScript 写的，天然语言无关，成了重写的“符合性测试金标准”，让 Agent 能自动验证 Rust 代码是否正确。第二，整个重写只用了 11 天，消耗了 59 亿输入 token 和 6.9 亿输出 token，按 API 价格算约 16.5 万美元。第三，重写后的 Bun 在 Claude Code 里已经跑了一个月，Linux 上启动速度快了 10%，但用户基本没感觉——Jarred 说“无聊就是好事”。这个案例证明了：当你有语言无关的测试套件和强大的编码 Agent 时，“重写”不再是禁忌，而是一个可管理的工程流程。
【关键术语小词典】
- Bun / Bun：一个 JavaScript 运行时，类似 Node.js 或 Deno，主打高性能。
- Zig / Zig：一种系统编程语言，强调手动内存管理和性能，Bun 最初就是用 Zig 写的。
- RAII / 资源获取即初始化：Rust 的一种自动内存管理机制，变量离开作用域时自动释放资源。
- Conformance Suite / 符合性测试套件：一套独立于语言的测试用例，用来验证实现是否符合规范。
【对你有啥用】
第一，这对你做决策智能平台的产品判断直接相关。你服务的电池、医药、钢铁客户，他们的排产算法或供应链系统往往也是多年积累的“老代码”，重构风险极高。这个案例告诉你：只要你有好的测试套件（比如客户的历史订单数据、排产结果验证集），AI Agent 可以帮你做“安全的重构”，这可以成为你跟客户沟通时的一个新卖点——“我们可以用 AI 帮你把遗留系统迁移到更稳定的架构上”。第二，从产品经理角度看，Jarred 的“对抗性代码审查”思路值得借鉴。他让 Agent 自己生成代码，然后让另一个 Agent 去审查，发现问题就修生成流程而不是修代码。这种“修流程而非修结果”的思路，完全可以搬到你的产品设计里——比如在供应链优化中，如果某个排程方案总是出问题，不是手动调参数，而是去优化生成方案的算法逻辑。第三，这个案例直接挑战了你对“AI 编码能力”的认知。以前你觉得 AI 只能写小函数或辅助调试，但现在它能在 11 天内完成百万行级别的重写。这意味着你可以在跟客户聊“AI 在工业软件中的应用”时，拿这个作为“AI 已经能处理复杂系统工程”的实证，而不是停留在“AI 能帮你写个 SQL 查询”的层面。

【一句话讲清楚它在说啥】
这篇论文提出一种叫 Jailbreak 的方法，让 LLM 直接读取数据库的底层存储文件，绕过 JDBC/ODBC 等传统驱动层，实现最高 27 倍的分析查询加速，且结果与标准查询完全一致。
【详细讲给你听】
背景：传统上，做数据分析时所有数据都得经过数据库驱动（比如 JDBC、ODBC）才能拿到，这些驱动是为事务查询设计的，不是为批量列式分析优化的，所以成了瓶颈。核心：作者搞了个 Jailbreak 方法，思路很简单——既然数据库文件格式的源码和文档都是公开的，那让 LLM 读这些资料，自动生成能直接解析存储文件的代码，跳过数据库引擎。关键细节：1）他们用 LLM 生成了针对 PostgreSQL 和 MySQL 存储文件的读取器，输出 Apache Arrow 格式，能被 DuckDB、Spark、cuDF 等直接消费。2）在 TPC-H 基准测试上验证了结果完全正确，且端到端分析吞吐量最高提升 27 倍。3）这个方法不限于 PG 和 MySQL，任何文件格式有文档或源码的数据库都能用。影响：这意味着以后做数据分析和 AI 应用时，可能不再需要传统数据库查询接口，直接读文件就能更快拿到数据，对数据仓库、实时分析、AI 训练数据管道都有颠覆性意义。
【关键术语小词典】
无特殊术语（JDBC/ODBC 是通用数据库连接标准，Apache Arrow 是跨语言的内存列式数据格式，TPC-H 是数据库性能基准测试，这些在工业软件领域是常识）
【对你有啥用】
1）你做的决策智能平台需要处理大量制造业数据（电池、钢铁等），客户常抱怨查询慢。这个思路可以直接用在你们的产品里：让 LLM 生成针对客户特定数据库（比如他们用的 Oracle、SQL Server）的存储文件读取器，绕过传统驱动层，给客户演示 10 倍以上的分析加速，这是非常硬的卖点。2）你关注 AI Agent 落地，这个研究展示了 LLM 不只是聊天，而是能直接操作底层系统文件。你可以思考：在供应链优化场景中，能不能让 Agent 直接读取 ERP 系统的存储文件，而不是通过 API 一层层调用？这会大幅降低集成复杂度。3）对产品经理来说，这个方向提示了一个新赛道：做“数据库文件格式解析中间件”或“LLM 驱动的数据管道加速器”，可以跟你们现有的排程算法产品打包，形成差异化竞争力。

背景：之前很多研究说“主动学习”比“被动接受”效果好，但具体到空间导航，到底主动控制能提升哪些记忆、哪些不能，一直没搞清楚。特别是儿童发展领域，大家默认主动参与肯定全面有益。

核心：这篇论文用了一个巧妙的实验设计。让4到10岁孩子玩一个地图游戏，帮小怪兽找最短路线去接五个朋友。一组孩子自己操作（主动组），另一组看别人操作（被动组）。结果发现，主动组对路径长度和路径之间围成的面积记忆更好，但对拐角数量这种细节记忆没差别，而且情景记忆（比如沿途发生了什么）也没提升。

关键细节：1）实验用了“配对设计”，每个主动组的孩子都有一个被动组的“分身”，确保两组经历完全一样，只是控制权不同。2）效果只体现在“全局路线特征”（长度、面积）上，不体现在“局部细节”（拐角数）上。3）主动导航对情景记忆（episodic memory）没有增强作用，说明这种好处是选择性的。

机制：可以理解为大脑在主动规划时，更关注“大局”——比如整体路线有多长、覆盖范围多大，因为这对决策有用。而拐角数量这种细枝末节，大脑觉得不值得额外分配资源去记。就像你开车去新地方，主动导航会让你记住大概方向和距离，但不会记住每个路口有几棵树。
【关键术语小词典】
Yoked experimental design / 配对实验设计：让主动组和被动组经历完全相同的刺激，只差控制权，用来精确分离“主动”本身的效果。
Episodic memory / 情景记忆：记住“何时何地发生了什么”的个人经历记忆，比如昨天午饭吃了什么。
Spatial memory / 空间记忆：记住空间位置、路径、方向的能力。
【对你有啥用】
1. 产品设计启发：如果你在做供应链排程或决策智能平台，用户“主动操作”和“被动看报表”的效果差异值得关注。比如让用户手动调整排产方案（主动），可能比直接给推荐方案（被动）更能让用户记住关键约束条件（如产能瓶颈、物料齐套），但对细节参数（如具体设备编号）记忆没帮助。这意味着交互设计上，关键决策点应该让用户主动参与，而细节参数可以自动填充。
2. 客户沟通话术：跟制造业客户聊产品时，可以引用这个逻辑：“我们平台让您主动调整排程方案，而不是只看结果，这样您能更快掌握整体产能瓶颈和物料覆盖范围，但具体到每个工单的细节，系统会自动处理。”这正好对应论文里“主动提升全局特征记忆，不提升细节”的结论。
3. 个人学习路径：作为PM，你在学习AI Agent和LLM应用时，可以主动动手搭建Demo或写Prompt，而不是只看教程。这样你对整体架构和关键接口（全局特征）记忆更深，但具体参数调优（细节）可以靠文档。这符合论文揭示的认知规律。
