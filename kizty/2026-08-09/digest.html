Superpowers：给编程 Agent 的完整开发方法论
obra/superpowers
GitHub Trending
⌄
https://github.com/obra/superpowers
【相关性评分】

【一句话讲清楚它在说啥】
一个叫 Superpowers 的开源框架，给 Claude Code、Cursor 等编程 Agent 装上后，Agent 会先问清需求、写规格、做计划，再按 TDD 流程自主干活，能连续自主编程几小时。
【详细讲给你听】
这事儿背景是现在编程 Agent 虽然能写代码，但普遍的问题是拿到需求就闷头开干，写出来的东西经常跑偏，或者代码质量堪忧。Superpowers 这个项目就是针对这个痛点来的。它不是一个简单的提示词，而是一整套方法论加可组合的技能包，装进 Claude Code、Cursor、Codex 这些主流编程工具里。核心流程是这样的：Agent 启动后不急着写代码，先跟你反复确认你到底要做什么，把需求提炼成一份你能读得完的规格说明。你确认后，它再生成一份实施计划，这份计划的标准是"一个品味差、没判断力、没项目背景、还讨厌写测试的初级工程师都能照着执行"。然后你说"开始"，它就启动子 Agent 驱动的开发流程，每个工程任务都有专门的 Agent 去执行、检查、评审，然后继续推进。作者说它的 Agent 经常能连续自主工作两小时不偏离计划。关键细节有三个：一是强调真正的红绿 TDD，就是先写失败测试再写代码让它通过；二是 YAGNI 原则，不提前做用不上的功能；三是 DRY，不重复造轮子。这套东西厉害在技能是自动触发的，你不需要额外操作，Agent 装上就有"超能力"了。目前支持 Claude Code、Cursor、Codex、Gemini CLI、Copilot CLI 等主流工具，而且 Claude Code 版本已经进了 Anthropic 官方插件市场。
【关键术语小词典】
TDD：测试驱动开发，先写会失败的测试，再写代码让它通过，保证代码质量。
YAGNI：You Aren't Gonna Need It，别做当前用不上的功能，避免过度设计。
DRY：Don't Repeat Yourself，别重复代码，抽象公共逻辑。
Subagent：子 Agent，主 Agent 派出去独立执行特定任务的辅助 AI。
【对你有啥用】
你天天跟排程算法和供应链优化打交道，这套"先规格后计划再执行"的流程，本质上是把软件工程的项目管理方法论搬到了 Agent 身上。你可以在自己的开发环境里装一个试试，用 Claude Code 或 Cursor 跑一个小工具，感受一下"Agent 先问你要什么"和"直接开写"的差别，这直接影响你对 AI 编程工具上限的判断。另外，你服务制造业客户，下次聊 AI 落地时，可以提这个案例说明"AI 不是拿来就用的，需要方法论约束"，这比空谈大模型能力有说服力得多。最后，这套框架里"子 Agent 驱动开发"的思路，跟你做决策智能平台里的多智能体协作是同一个逻辑，值得拆解它的任务分解和评审机制。

工具调用的苦涩教训
The Bitter Lesson of Tool Calling
arXiv · Ishan Patel, Sahil Sen, Elias Lumer, Vamse Kumar Subbiah · 3 天前
⌄
http://arxiv.org/abs/2608.06370v1
【相关性评分】
9
【一句话讲清楚它在说啥】
这篇论文对比了让大模型用写代码的方式调用工具，和传统用 JSON 格式调用工具的效果。结果发现前者在大多数模型上表现更好，尤其对 GPT-5.6 提升明显，而且更稳定。
【详细讲给你听】
背景是这样的，现在大模型要调用外部工具，比如查天气、操作软件，主流做法是让模型输出一个 JSON 格式的指令，然后系统去执行。但 JSON 格式有局限，比如复杂逻辑写起来很别扭，多个操作要串行执行，效率不高。这篇论文提出一个新思路，干脆让模型直接写 Python 代码来调用工具，代码可以自然实现循环、条件判断、并行执行这些复杂操作，执行完结果直接返回给模型，一个回合搞定。

他们拿了 14 个主流模型在 BFCL v4 这个标准测试集上做对比。结果很直接，程序化调用在 11 个模型上不输甚至超过 JSON 调用，GPT-5.6 家族平均提升了 10.6%。在需要并行处理多个任务的场景下，14 个模型里有 13 个表现更好或持平。更关键的是稳定性，当上下文被干扰时，JSON 调用平均掉 2.3% 的准确率，而程序化调用几乎不受影响。

这个结果其实呼应了 AI 领域一个经典观点，叫"苦涩的教训"，就是说与其花心思设计复杂的规则和格式，不如给模型更多自由度和计算能力，让它自己学会怎么用工具。代码本身就是一种更灵活、更强大的表达方式，模型写代码比填表格更自然。这也说明未来 Agent 的交互方式可能会从"结构化数据"转向"写程序"。
【关键术语小词典】
PTC / 程序化工具调用：让模型写 Python 代码来调用工具，代码即指令。
JSON Tool Calling / JSON 工具调用：模型输出固定格式的 JSON 数据来指定调用哪个工具和参数。
BFCL v4 / 伯克利函数调用排行榜第四版：业界常用的评估模型调用工具能力的标准测试集。
Context Rot / 上下文腐化：对话变长或插入干扰信息后，模型对早期指令的遵循能力下降。
【对你有啥用】
第一，你做的决策智能平台，如果底层接 LLM 来操作排程算法或供应链优化模块，现在可以认真考虑让模型输出代码而不是 JSON 来触发计算。尤其是排产这类需要多步迭代、条件分支的场景，代码表达比 JSON 灵活得多，客户现场改规则也更容易。第二，跟客户聊产品架构时，可以拿这个结论当论据，说明为什么 Agent 层要支持"代码即接口"的设计，而不是只做简单的 API 调用，这能体现你们在 AI 原生交互上的技术判断。第三，你自己在学 Agent 和 LLM 应用，这个方向值得跟进，后续主流框架比如 LangChain 或 OpenAI 的 Agent SDK 大概率会往这个方向演进，提前理解底层原理对你做产品选型有帮助。

【一句话讲清楚它在说啥】
Anthropic 把 Claude Code 的自动模式设为默认，并发布评测证明它比人类审核更安全，能拦截 89% 的危险操作，但独立验证和恶意包攻击仍是隐患。
【详细讲给你听】
背景是编码智能体越来越强，但安全问题一直让人头疼。以前用 Claude Code 这类工具，每执行一步都要弹窗让你点确认，点多了就麻木了，反而容易放行真正的危险操作。Anthropic 这次直接摊牌，从 8 月 14 号起，Pro、Max 和 Team 套餐的新会话默认开启自动模式，不再频繁打断你。他们拿数据说话，找了 1053 个付费测试者，中途把某个权限请求偷偷换成明显有害的命令，结果只有 13.6% 的人类拒绝了，而自动模式能拦下其中 89% 的攻击。这逻辑很直接，人点确认点多了就是摆设，机器反而更警觉。但作者 Simon Willison 也泼了冷水，说还有 11% 漏网之鱼，而且更担心的是提示注入，就是恶意指令藏在第三方包或网页内容里骗过智能体。Anthropic 找第三方机构 Trajectory Labs 测了 720 次攻击，全部被 Claude Fable 5、Opus 5 和 Sonnet 5 的自动模式挡下，零成功。不过作者举了个例子，恶意 npm 包让你先跑一条看似正常的命令，实际把数据全偷走，这种场景自动模式未必防得住。他 2026 年初预测过编码智能体会出安全事故，现在希望被打脸，但想要更多独立验证。
【关键术语小词典】
Auto mode / 自动模式：智能体自主执行操作，不再每一步都等人类确认。
Prompt injection / 提示注入：把恶意指令藏在正常内容里，骗智能体执行危险操作。
Data exfiltration / 数据外泄：把系统里的敏感数据偷偷传出去。
Trajectory Labs：第三方安全评测机构，专门测试 AI 模型的安全性。
【对你有啥用】
第一，你做决策智能平台，客户最怕的就是 AI 乱动生产数据。Anthropic 这套“自动模式 + 评测数据”的打法，可以直接借鉴到产品设计里，跟客户聊安全时，别光讲理论，拿出“人类审核只有 13.6% 拒绝率”这种对比数据，说服力强得多。第二，提示注入这个坑，在供应链场景里更隐蔽，比如排产系统读了供应商发来的异常 BOM 文件，可能就被带偏了。你可以在产品里加一层“内容来源可信度”校验，或者对高风险操作强制二次确认，而不是一刀切全自动。第三，Anthropic 敢把默认行为改成自动模式，说明他们对自家模型的安全边界很有信心，这会影响你选型时对 Claude 系列的评估，值得跟进他们后续发布的 evals 报告。

Claude Code 的权限模式原本分几种，默认是每次操作都要人工确认的 default 模式，Auto mode 则是让 AI 自主执行、只在风险操作时拦截。Anthropic 这次把 Auto mode 设为 Pro/Max/Team 套餐的默认，相当于默认信任 AI 的判断，而不是默认怀疑。背后的逻辑是：人类对频繁弹窗会麻木，反而降低安全性。但这类自主模式的边界在于，它主要靠内置分类器识别已知危险操作，对提示注入这类把恶意指令藏在正常内容里的攻击，防护效果还没被充分验证。

- SSO / 单点登录：一次登录就能访问多个关联系统的认证机制。
