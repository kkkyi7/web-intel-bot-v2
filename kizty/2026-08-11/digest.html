【一句话讲清楚它在说啥】
Anthropic 把 Claude Code 的自动模式设为默认，并发布评测证明它比人类审批更安全，能拦截 89% 的危险操作，同时声称已基本解决提示注入攻击。
【详细讲给你听】
这事儿背景是 AI 编程助手越来越强，但安全问题一直让人头疼。以前用 Claude Code 这类工具，每执行一步操作都要你点确认，烦不说，点多了人就麻木了，反而容易放行危险操作。Anthropic 现在直接把自动模式设为默认，意思是让 AI 自己判断要不要执行命令，不再频繁打断你。他们拿数据说话：找了 1053 个付费测试者，中途把正常操作偷偷换成危险命令，结果只有 13.6% 的人类拒绝了，而自动模式能拦下其中 89% 的危险操作。这个对比挺扎心，说明人点确认这事儿确实不靠谱。更猛的是他们请第三方机构 Trajectory Labs 测了 720 次间接提示注入攻击，全部失败，用的是最新的 Claude Fable 5、Opus 5 和 Sonnet 5 模型。但作者 Simon Willison 留了个心眼，他举了个例子：一个恶意第三方包，让你先跑一条命令下载模型文件，再跑测试，而那条命令本身就是偷数据的。这种场景下，自动模式未必能识别出来。他之前预测 2026 年编程 Agent 会出大事故，现在希望被打脸，但还需要更多独立验证。
【关键术语小词典】
Auto mode / 自动模式：Claude Code 里 AI 自主决定执行哪些操作，无需人类逐步确认。
Prompt injection / 提示注入：把恶意指令藏在 AI 读取的内容里，诱导它执行危险操作。
Data exfiltration / 数据窃取：通过隐蔽手段把系统里的敏感数据偷偷传出去。
Trajectory Labs / 轨迹实验室：Anthropic 委托的第三方安全评测机构。
【对你有啥用】
第一，你做决策智能平台，客户最怕的就是 AI 乱操作。Anthropic 这个"自动模式比人审批更安全"的数据，可以直接拿来跟制造业客户讲，帮他们理解为什么 AI 自主决策反而比层层审批更可靠，尤其是排产算法这种高频操作场景。第二，提示注入这个问题，你在做供应链 AI 应用时一样会遇到，比如 AI 读取供应商邮件或 BOM 文件时被植入恶意指令。Anthropic 说解决了，但 Simon 的质疑提醒你别全信，跟客户聊安全方案时留个余地。第三，这个评测方法值得学，用"人类 vs AI 拦截率"的对比来做产品安全验证，你以后给平台做安全测试或写产品文档时可以直接套用这个框架。

【一句话讲清楚它在说啥】
GitHub 的模型聚合服务 GitHub Models 已经正式关停，作者在 Actions 里跑自动化任务时收到报错才发现。他猜测原因是编码智能体让免费送 token 的模式撑不住了，自己已切换到 OpenAI 付费 API。
【详细讲给你听】
这事儿得从 GitHub Models 的定位说起。它不是一个模型，而是一个中转站，把 OpenAI、Anthropic、Meta 等各家大模型统一成一个 API，让你在 GitHub 的生态里直接调用。最妙的是，你在 GitHub Actions 里跑代码时，能直接用仓库里现成的 GitHub token 去调模型，不用自己配密钥。这跟 GitHub 之前提的 Continuous AI 概念是一套的，就是让 AI 调用成为 CI/CD 流水线里的一等公民。作者 Simon Willison 一直在用这个服务，给自己的开源项目自动生成文件夹摘要，跑在 GitHub Actions 里，零成本。结果今天他的自动化任务突然报错，说服务在退役期的限流中，再一看，已经彻底关了。GitHub 没解释原因，但作者判断，核心问题在于成本。以前大家用 GitHub Models 是薅羊毛，跑点小任务无所谓。但现在编码智能体流行起来了，一个 agent 可能一晚上跑几百次模型调用，如果还免费或者补贴着，GitHub 扛不住。他现在的做法是换成 OpenAI 的 API key，设了月度消费上限，用 GPT-5.6 Luna 继续生成摘要。这事儿对做 AI 产品的人是个信号，免费 API 的窗口期在收窄，所有依赖第三方免费额度的自动化流程都得重新评估。
【关键术语小词典】
GitHub Models：GitHub 提供的多模型统一 API 服务，现已关停，主要用于 Actions 内调用 LLM。
GitHub Actions：GitHub 的 CI/CD 自动化服务，可以在代码仓库里跑定时任务或事件触发任务。
Continuous AI：GitHub 提出的概念，指把 AI 调用嵌入到持续集成和部署的流程中。

机制或影响：Smalltalk 的核心机制是"镜像"和"活对象"。传统开发是写代码、编译、运行，Smalltalk 是直接在一个运行中的系统里改代码，改完立刻生效。这带来的好处是调试效率极高，坏处是性能开销大、部署模型和现代云原生不兼容。这次发布的意义在于，它提醒我们当前 AI 编程工具和低代码平台追求的"即时反馈"和"可视化调试"，其实 Smalltalk 四十年前就做过了。
