【一句话讲清楚它在说啥】
这是一个开源项目，用 AI Agent 自动解析简历 PDF，提取结构化信息，再结合 GitHub 数据，给出一份带分数、证据和扣分项的客观评估报告。
【详细讲给你听】
背景：传统简历筛选靠 HR 或招聘经理手动看，费时且容易有偏见。很多公司想用 AI 辅助，但市面上要么是黑盒评分，要么只做关键词匹配，缺乏可解释性和公平性。
核心：InterviewStreet 开源了一个叫 Hiring Agent 的工具，把简历筛选流程自动化了。它先用 PyMuPDF 把 PDF 转成 Markdown 文本，然后调用本地或云端的大模型（比如 Ollama 上的 Gemma 或 Google Gemini），按“基本信息、工作经历、教育、技能、项目、奖项”这几个板块分别提取结构化数据。关键一步是，它还会从简历里抓取 GitHub 用户名，拉取该用户的 profile 和仓库信息，让大模型挑出最相关的 7 个项目，用来验证简历里的技术栈和项目经验是否真实。最后，评估模块会基于严格规则打分，输出带类别分数、证据、加分和扣分项的评估报告，整个过程支持完全本地运行，保护数据隐私。
关键细节：1）模块化设计，每个环节（PDF 解析、LLM 调用、GitHub 增强、评分）都是独立模块，方便替换或定制。2）支持多种大模型后端，包括本地 Ollama 和云端 Gemini，开发者可以自由选择。3）输出 CSV 格式，方便批量处理和后续分析。
机制或影响：这个项目展示了 AI Agent 在 HR 场景的落地方式——不是简单替换人，而是把筛选过程拆解成可解释的步骤，让招聘方能看到“为什么给这个分数”。对开发者来说，它提供了一个现成的 pipeline，可以快速集成到自己的招聘系统里。
【关键术语小词典】
- Ollama：一个本地运行大模型的工具，不用联网，保护数据隐私。
- JSONResume：一种标准化的简历 JSON 数据格式，方便程序处理。
- PyMuPDF：一个 Python 库，用来读取和转换 PDF 文件。
- Jinja：一种模板引擎，这里用来定义给大模型的指令模板。

1. 产品设计启发：这个项目的模块化思路（PDF 解析 -> LLM 提取 -> 外部数据增强 -> 评分）可以直接借鉴到你做的决策智能平台。比如在供应链排产场景，你可以把“简历”换成“生产订单”，把“GitHub 信号”换成“设备状态数据”，构建一个类似的评估 pipeline。

相同证据不同答案：多模态大模型顺序敏感性审计
Same Evidence, Different Answer: Auditing Order Sensitivity in Multimodal Large Language Models
arXiv · Akshay Paruchuri, Sanmi Koyejo, Ehsan Adeli · 昨天 17:53
⌄
http://arxiv.org/abs/2606.26079v1
【相关性评分】

【一句话讲清楚它在说啥】
这篇论文发现，目前最强的多模态大模型（比如Gemini、GPT-4V）在输入顺序打乱后，有24%到50%的概率给出不同答案。作者开发了一个叫Facet-Probe的审计工具，系统测试了18个模型，结论是光靠改提示词解决不了这个问题，得从训练和架构层面下手。
【详细讲给你听】
背景是这样的：现在评测多模态大模型，都是按固定顺序给题目打分，但没人关心如果把选项、图片、文档的顺序打乱，模型会不会变答案。这其实是个基础可靠性问题，就像你问一个人“苹果和香蕉哪个好”，换个顺序问“香蕉和苹果哪个好”，答案应该一样才对。核心发现是，作者测试了18个前沿模型（包括闭源和开源），没有一个能做到顺序不变。具体数据很扎心：按不同维度测，平均答案翻转率在24%到50%之间。就算是最强的模型，在13.4%的测试里答案也会变。作者还做了个控制实验，把Gemini在温度设为0（最确定模式）下跑同一道题，发现顺序导致的答案变化远超模型自身的随机波动。更关键的是，他们试了各种提示词技巧来缓解这个问题，结果发现这些技巧只对文本有效，对图片推理完全没用。这意味着，想靠写更好的提示词来让模型稳定，这条路走不通。机制上，这暴露了当前多模态模型的一个根本缺陷：它们处理信息时对顺序敏感，本质上是因为注意力机制和模态融合方式没有做到真正的“置换不变性”。影响是，如果你用这些模型做供应链决策、排产建议或者客户分析，同样的输入换个顺序可能得到完全不同的结论，这对工业场景是致命问题。
【关键术语小词典】
MLLM / 多模态大语言模型：能同时处理文字、图片、文档等多种输入类型的AI模型。Facet-Probe / 多面审计工具：作者开发的测试框架，从五个维度（选项顺序、证据块顺序、文档排名、图片集顺序、混合模态顺序）检测模型稳定性。Flip Rate / 翻转率：输入顺序打乱后，模型给出不同答案的比例。Order-Invariant / 顺序不变性：模型对输入顺序不敏感，是可靠AI的基本要求。
【对你有啥用】
第一，这对你做供应链优化和排程算法产品直接相关。你服务的客户（电池、医药、钢铁）在输入生产数据时，顺序往往是随机的。如果AI模型对顺序敏感，同样的BOM表换个顺序可能算出不同的排产结果，这会让客户对AI决策失去信任。下次跟客户聊时，可以主动问“你们的数据输入顺序是否固定”，然后解释这个研究发现。第二，作为PM，你正在学习AI Agent和LLM应用，这个研究告诉你一个关键的产品判断：不要过度依赖提示词工程来保证可靠性。很多Agent产品靠写复杂的prompt来稳定输出，但论文证明这条路有天花板。你在设计产品架构时，应该考虑在后端加入“顺序鲁棒性测试”作为质量门禁。第三，这个Facet-Probe审计框架本身可以变成产品功能。你所在的平台是做决策智能的，完全可以把“顺序敏感性检测”作为一个增值模块卖给客户，帮他们验证AI输出的稳定性，这比单纯讲算法精度更有说服力。

【背景知识】
多模态大模型（如GPT-4V、Gemini）处理输入时，通常依赖自注意力机制来融合文本、图片、文档等不同模态的信息。但注意力机制本身对输入顺序敏感——它天然不具备置换不变性，这意味着打乱选项、图片或文档的顺序，模型内部计算出的注意力分布会变，最终输出就可能不同。这篇论文用Facet-Probe工具系统测了18个模型，发现即使把温度设为0（确定性输出），顺序导致的答案翻转率仍远超模型自身的随机波动，说明这不是推理噪声，而是架构层面的固有问题。更关键的是，他们试了各种提示词技巧（如强调顺序无关、要求逐步推理），发现这些技巧对纯文本任务有一定缓解效果，但对涉及图片推理的任务完全无效——这基本堵死了靠工程调参来修复这条路。

How Robust is OCR-Reasoning? Evaluating OCR-Reasoning Robustness of Vision-Language Models under Visual Perturbations
arXiv · Yuxing Cheng, Yuan Wu, Yi Chang · 昨天 17:15
⌄
http://arxiv.org/abs/2606.26041v1
【相关性评分】

【一句话讲清楚它在说啥】
这篇论文测试了18个视觉语言模型在图像被加噪、模糊、旋转等干扰下的OCR推理能力，发现模型准确率高不代表抗干扰强，图表比文档更容易出错。
【详细讲给你听】
背景是现在视觉语言模型在OCR任务上表现不错，但大家很少关注一个实际问题：如果输入图片质量变差——比如拍糊了、有噪点、角度歪了——模型的推理能力会掉多少。这恰恰是工业场景的常态，工厂里的单据、屏幕截图、设备标签很少是完美清晰的。核心是作者搞了个叫OCR-Robust的测试集，包含812个样本，分两类：一类是文档、手写、收据这种传统OCR内容，另一类是图表、几何图、表格这种结构化内容。他们从18种可能的图像干扰中挑了5种最具代表性的（比如高斯噪声、模糊、旋转），每种设3个严重等级。然后测了18个模型，包括闭源的开源的以及OCR加LLM的流水线方案。关键发现有三点：第一，干净数据上准确率高的模型，在干扰下不一定更稳，有些反而掉得更狠。第二，最差情况下的性能退化很严重，尤其对结构敏感的任务。第三，图表和表格比普通文档脆弱得多，稍微加个噪点推理就崩了。用的评估指标除了常规的干净准确率，还搞了相对保留率、最差保留率和综合鲁棒性指数，挺系统的。
【关键术语小词典】
OCR推理：让模型不仅识别图片里的文字，还要理解文字含义并做逻辑判断。视觉扰动：对图像施加的噪声、模糊、旋转等人为破坏，模拟真实场景中的图像退化。CRI：综合鲁棒性指数，一个把多个维度表现打包成一个分数的指标。
【对你有啥用】
第一，你做的决策智能平台如果涉及从工厂报表、质检单、设备屏幕截图里提取数据做排产或优化，这个研究直接告诉你：别信模型的基准测试分数，要在真实有噪点的图片上测。第二，给客户演示时，可以主动提“我们测试过在模糊/反光/倾斜条件下的识别稳定性”，这是竞品很少讲但客户在意的痛点。第三，如果你在评估用哪个视觉模型做供应链单据解析，这篇论文的18个模型对比表能帮你快速排除那些“干净数据好看但一碰就碎”的模型，省掉自己踩坑的时间。

【背景知识】
这篇论文的核心是给视觉语言模型（VLM）做压力测试——不是看它们在完美图片上的OCR准确率，而是模拟工业现场常见的烂图场景：模糊、噪点、旋转。结果发现很多模型在干净数据上分数漂亮，但一遇到真实干扰就崩得厉害，尤其是图表、表格这类结构化内容比普通文档更脆弱。这对做工业AI产品的人来说是个提醒：基准测试的分数不能直接信，得拿客户现场拍的照片重新测一遍。

【关键术语小词典】
- 模型蒸馏 / Model Distillation：用大模型（如 Claude）的输出训练小模型，让小模型学到大模型的能力。
