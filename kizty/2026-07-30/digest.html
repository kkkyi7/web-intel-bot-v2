【一句话讲清楚它在说啥】
OpenAI 发现 GPT-5.6 的 API 里有两个开关——保留推理痕迹和启用压缩——同时打开后，在视觉推理测试 ARC-AGI-3 上的得分直接翻了三倍，说明模型推理过程的“可见性”和“精简度”对复杂任务至关重要。
【详细讲给你听】
背景是 ARC-AGI-3 这个测试专门用来衡量 AI 的抽象推理能力，不是靠背数据就能过的。之前大家觉得模型在这个测试上表现一般，可能得换架构或者大力出奇迹。但 OpenAI 这次发现，根本不用动模型本身，只需要在 API 调用时打开两个设置：一个是“保留推理链”（keep reasoning），让模型把思考过程完整写出来；另一个是“启用压缩”（enable compaction），让模型在输出最终答案前把推理链压缩成更简洁的格式。结果很惊人：得分从原来的不到 20% 直接飙到 60% 以上，翻了不止三倍。关键细节是，这两个设置单独开效果都不行，必须同时用。推理链保证了模型不“偷懒”跳步骤，压缩则强迫模型提炼核心逻辑，相当于让模型既“想清楚”又“说清楚”。这对工业软件和决策智能产品来说，意味着模型输出的可解释性和效率可以兼得，不再是非此即彼的 trade-off。
【关键术语小词典】
- ARC-AGI-3 / 抽象推理语料库-通用智能 3：一个专门测试 AI 抽象推理能力的基准，强调“举一反三”而非记忆。
- Reasoning Chain / 推理链：模型在生成答案前，逐步展示其思考过程的文本记录。
- Compaction / 压缩：将冗长的推理链精简为关键逻辑步骤，保留核心信息但减少冗余。
【对你有啥用】
1. 产品设计启发：你做的排程算法和决策智能平台，可以借鉴这个“推理链+压缩”思路。给客户展示 AI 建议时，先展示完整推理过程（增加信任），再输出一个压缩版结论（便于决策）。这能直接解决制造业客户对 AI 黑箱的抵触。
2. 客户沟通话术：下次跟电池或钢铁客户聊，可以提“我们不仅给结果，还能让模型把思考过程写出来，再提炼成一句话结论”。这比单纯说“准确率高”更有说服力，因为工业场景需要可审计。
3. 学习路径调整：你在学 AI Agent 和 LLM 应用，这个发现提示你：调参和 prompt 工程之外，API 层面的“可见性”设置可能是下一个关键杠杆。可以深入研究 OpenAI 的 reasoning_effort 和 response_format 参数，这比追新模型更实用。

【详细讲给你听】
背景是现在大家都在吹AI智能体多厉害，但现有的测试方法要么任务太简单（比如只问个问题），要么不看成本。这篇论文的团队觉得，真正有用的AI智能体得能在办公软件里干长周期的活，而且得算经济账。他们搞了个叫OmegaUse-OfficeVal的基准，里面包含了100个从真实办公需求里提炼出来的任务，平均每个任务需要人类花2.32小时才能完成。核心创新是给每个任务绑了两个经济信号：一个是人类完成它需要多少时间，另一个是任务的“价格代理”（可以理解成公司愿意为这个任务付多少钱）。这样就能直接对比AI的推理成本和人类的人力成本。他们测了几个最前沿的大模型，结果发现：虽然AI比人类便宜得多、快得多，但做出来的东西质量还达不到人类水平。比如让AI做一个带复杂公式的Excel表格，它可能很快搞出来，但公式逻辑有漏洞。这个基准完全开源，代码和数据都能拿到。

【详细讲给你听】
背景是现在很多团队用CLAUDE.md或系统提示词写长政策文档，试图让AI智能体自动遵守规则。但这篇论文和HN用户反馈揭示了一个核心问题：长上下文模型存在严重的“中间迷失”现象。用户mcdeltat分享真实体验，Claude在开始10分钟内能遵守指令，之后就会忽略CLAUDE.md里的要求，比如禁止写大段注释或必须用现有功能。用户wongarsu指出，人类自己面对长政策文档也常犯错，模型失败的原因类似：工作记忆有限、推理深度受限。关键细节是，用户发现如果在任务进行中直接提示规则，效果反而更好。这本质上是模型KV缓存和采样器质量导致的，用户DiabloD3甚至建议本地推理能改善。机制上，模型对长上下文的注意力会衰减，尤其是中间部分的信息容易被忽略，这和2023年那篇“Lost in the Middle”论文结论一致。影响是，依赖长文档做智能体治理的方案需要重新设计，不能指望模型自动记住所有规则。
【关键术语小词典】
- KV cache：键值缓存，模型处理长文本时存储中间计算结果的机制，质量影响长上下文效果
- Lost in the Middle：中间迷失，模型对长文本中间位置信息的注意力显著低于开头和结尾
