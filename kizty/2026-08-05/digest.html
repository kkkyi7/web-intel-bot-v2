AirLLM：单张4GB显卡跑70B大模型
lyogavin/airllm
GitHub Trending

【一句话讲清楚它在说啥】
AirLLM 这个开源工具能大幅降低大模型推理时的显存占用，让 70B 甚至 671B 的超大模型在普通单张显卡上跑起来，不用量化、剪枝或蒸馏，原理是分层加载和按专家流式加载。
【详细讲给你听】
背景是，大模型越来越大，动辄几百B参数，普通开发者手里那张 4GB 或 8GB 的显卡根本装不下，更别说推理了。之前行业主流做法是量化、剪枝、蒸馏，把模型压缩到能塞进显存，但会牺牲精度或效果。AirLLM 的思路不一样，它不做压缩，而是改变加载方式。核心是把模型按层切分，一次只加载一层到显存里算，算完就释放，再加载下一层，这样显存占用就只跟单层大小有关，跟模型总大小无关。后来 v3.0 又针对 MoE 架构模型做了优化，因为 MoE 模型推理时每个 token 只激活部分专家，AirLLM 就按专家流式加载，只把被激活的专家拉进显存，所以能跑更大的模型。关键细节有几个，比如 70B 模型在 4GB 显卡上跑，DeepSeek-V3 671B 只要约 12GB，最新的 Kimi K3 2.8T 参数在单张 RTX 6000 Ada 上实测只占 3.72GB 显存。还有个细节是它支持 FP8 格式，进一步减半显存占用。影响是，这大大降低了超大模型的使用门槛，个人开发者或小团队不用买昂贵的多卡服务器，就能本地跑顶级开源模型做实验和产品原型。
【关键术语小词典】
MoE 混合专家模型：把模型拆成多个专家网络，每次推理只激活部分专家，省算力。
FP8 8位浮点数：一种低精度数值格式，能减少模型体积和显存占用。
显存 VRAM：显卡上的专用内存，决定能加载多大的模型。
量化：把模型参数从高精度转成低精度来压缩体积，可能损失精度。
【对你有啥用】
第一，你做的决策智能平台如果要给制造业客户做本地化部署，客户现场往往没有高端 GPU 集群，AirLLM 这种分层加载思路可以直接借鉴，让你们的排程优化模型在客户已有的普通服务器上跑起来，降低交付硬件门槛。第二，你关注 AI Agent 和 LLM 应用，现在可以用 AirLLM 在本地显卡上跑 Qwen3-235B 或 DeepSeek-V3 这类顶级开源模型做产品原型验证，不用依赖云 API，数据不出本地，这对跟电池、医药这类注重数据安全的制造业客户沟通时是个很好的卖点。第三，下次跟客户聊 AI 落地成本时，可以提这个案例，说明现在跑大模型不一定要买高端算力，软件层面优化也能大幅降本，这能帮你在方案汇报中体现技术洞察力。

大模型推理的显存瓶颈一直是个硬约束，传统思路是量化、剪枝、蒸馏这些'压缩'手段，但都有精度损失或效果打折的问题。AirLLM 换了个角度，不做压缩，而是把模型按层切分，推理时只加载当前计算的那一层到显存，算完就释放，再加载下一层，这样显存占用只跟单层大小有关，跟模型总大小无关。这个思路的代价是速度慢，因为要反复在磁盘和显存之间搬运权重，所以它更适合离线批处理或原型验证，不太适合高并发的在线服务。后来针对 MoE 架构又做了优化，因为 MoE 每次推理只激活部分专家，AirLLM 就按专家流式加载，只拉被激活的专家进显存，所以能跑更大的模型。

Uber 开源 ADR：企业 AI 代理安全检测与响应系统

【一句话讲清楚它在说啥】
Uber 开源了 ADR 系统，专门监控和保护企业里用的 AI 代理（比如 Claude Code、Cursor），能检测攻击、评估风险、阻止危险操作，已在 Uber 生产环境跑起来了。
【详细讲给你听】
背景：现在企业里员工开始用 Cursor、Claude Code 这类 AI 编程工具干活，客户那边也有 AI 客服代理。但这些代理能访问代码库、内部系统，一旦被提示注入攻击或者恶意操纵，泄露的就是企业核心资产。之前这块基本是空白，安全团队看不到代理在干嘛。

核心：Uber 搞了个 ADR 系统，四层防护。第一层 Observability，跨 7 种以上 AI 编程工具抓取代理的意图、工具调用和执行轨迹，在 macOS、Linux、Windows 上都能跑。第二层 Benchmark，搞了 300 多个测试任务、133 个 MCP 服务器，覆盖 17 种代理攻击技术，用来评估防御能力。第三层 Detection，双代理架构，先用高召回率做初筛，再对可疑会话做深度推理。第四层 Prevention，直接阻止危险操作，但这部分没开源。

关键细节：论文被 MLSys 2026 接收，说明学术认可度不低。开源部分包括 Sensor、Benchmark 和 Detector，离线红队引擎没放出来。检测器支持 Anthropic 和 OpenAI 的 key，还能用 llamafirewall 做无 key 冒烟测试。

影响：这相当于给 AI 代理装了个监控摄像头加防火墙。对做企业级 AI 产品的团队来说，安全不再是事后补丁，而是产品上线前就要过的关卡。Uber 把生产级方案开源，等于给行业立了个标杆。
【关键术语小词典】
ADR：Agentic AI Detection and Response，代理式 AI 检测与响应系统，专门保护 AI 代理的安全。
MCP：Model Context Protocol，模型上下文协议，让 AI 代理能调用外部工具和数据的标准接口。
Prompt Injection：提示注入，通过构造恶意输入让 AI 代理执行非预期操作的攻击方式。
MLSys：Machine Learning and Systems，机器学习和系统领域的顶级学术会议。
【对你有啥用】
第一，你做的决策智能平台如果接入了 AI 代理帮客户做排程或供应链优化，ADR 的 Observability 思路可以直接借鉴，给客户展示代理每一步的决策依据和工具调用轨迹，这能大幅降低客户对 AI 的信任门槛。第二，ADR-Bench 的 17 种攻击技术清单是个现成的安全评估框架，下次跟制造业客户聊 AI 落地，可以主动提你们有对应的安全检测方案，这比单纯讲算法效果更有说服力。第三，双代理检测架构（高召回初筛加深度推理）这个思路可以迁移到你的产品里，比如先快速过滤异常订单再对可疑的做深度分析，能省不少算力成本。

【一句话讲清楚它在说啥】
Simon Willison 发布了命令行工具 LLM 0.32，支持显示模型推理过程、调用服务端工具（如代码执行和联网搜索）、重写了日志系统，并默认切换到 GPT-5.6 Luna 模型。
【详细讲给你听】
背景：LLM 是 Simon Willison 做的开源命令行工具，让你在终端里直接调用各种大模型。之前它只能发消息收文本，但模型能力进化了，会思考、会调工具、会返回图片，旧架构撑不住了。核心：这次 0.32 是大版本更新。最亮眼的是能看见模型的推理轨迹，就是它"心里想什么"会单独显示，不混进你管道输出的正式结果里。然后支持了服务端工具，比如 OpenAI 的代码解释器和联网搜索，你直接让模型跑 Python 或查资料。还加了 llm openai endpoint 命令，一行代码连任何兼容 OpenAI 接口的本地模型，比如 LM Studio 里的 Gemma。Python API 也改了，支持一次性传完整消息历史，并且能流式接收推理文本、工具调用、图片等混合事件。关键细节：GPT-5.6 Luna 成为默认模型，便宜且能力强；llm-anthropic 插件新增 WebSearch、WebFetch、CodeExecution 和 AnthropicMCP，后者能让你在单次请求里让 Claude 调用你的 MCP 服务查数据库。影响：对开发者来说，这工具把"调模型"这件事从玩具变成了正经开发环境，尤其是调试推理模型和工具调用时，能看见思考过程太重要了。
【关键术语小词典】
Reasoning traces / 推理轨迹：模型在给出答案前内部生成的思考步骤，现在可以单独查看。
Server-side tools / 服务端工具：由模型提供商在云端执行的工具，如代码解释器、联网搜索，无需本地配置。
MCP / 模型上下文协议：让 AI 模型能调用外部数据源和工具的标准接口。
Content-addressable logs / 内容寻址日志：根据内容本身生成唯一标识来存储日志，方便去重和追溯。
【对你有啥用】
第一，你搞决策智能平台，推理轨迹可视化这个思路可以直接搬到产品里。给客户展示排产或供应链优化结果时，如果能让决策过程"可见"，比如显示算法考虑了哪些约束、为什么选这个方案，客户信任度会大幅提升。第二，llm openai endpoint 这个命令对你调试本地模型很有用。你研究 AI Agent 时，可以用它快速对比不同模型在同样 prompt 下的表现，不用装一堆环境。第三，AnthropicMCP 这个模式提示你：未来企业级 AI 平台的竞争点在于"模型能不能无缝调用客户已有的数据系统"。你跟客户聊的时候，可以提"我们支持 MCP 标准，能直接连你们的数据库和 API"，这会是个差异化卖点。

- Embedding：嵌入模型，把文字变成数字向量的工具，是记忆检索的基础
【对你有啥用】

背景是，随机对照试验在科技公司、药企和政府机构里都是做因果推断的黄金标准，但传统的均值差估计器虽然无偏，精度不够，尤其当处理效应不均匀或者结果分布有重尾时。过去有很多改进方法，比如协变量调整、方差缩减，但最近研究发现没有一个估计器能在所有数据集上表现最好。这篇论文的核心思路是，别为单个试验找最优估计器，而是按分析目标在试验族里选。他们用样本分割来估计评估指标的分布，比如均方误差和后悔值，然后系统比较估计器，还保持了渐近保证。关键细节是，他们用亚马逊供应链优化技术试验和民主强化挑战数据集做了验证，结果发现加权最小二乘在推断目标下表现最好，而均值差在决策场景下最小化后悔值。这对供应链的商业价值很直接，因为实验评估直接影响决策质量，选错估计器可能带来错误结论和资源浪费。
【关键术语小词典】
RCT / 随机对照试验：随机分组比较干预效果的标准实验方法。
Difference-in-means / 均值差估计器：简单比较两组平均结果的估计方法。
Regret / 后悔值：决策中实际损失与最优决策损失的差距。
WLS / 加权最小二乘：给不同数据点不同权重的回归估计方法。
【对你有啥用】
这个框架的思路可以直接搬到你的排产算法评估里。你在做供应链优化时，经常要对比不同算法或参数配置的效果，但单一指标可能误导决策。比如客户关心的是决策质量还是推断精度，你可以用类似样本分割的方法，在历史数据上评估不同评估指标的表现，再选合适的比较方式。另外，文中提到亚马逊供应链试验，说明大厂也在用类似方法优化实验评估，下次跟客户聊实验设计或效果评估时，可以提这个案例，体现你对方法论深度的理解。最后，这个框架强调按分析目标选工具，也提醒你在产品设计里，给客户提供的分析模块应该区分推断和决策场景，而不是一刀切。

【详细讲给你听】

X-Atlas：Xaira 自建的因果扰动数据集，信息量是传统表达谱数据的 30 倍。
