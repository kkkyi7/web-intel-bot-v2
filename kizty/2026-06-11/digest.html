【详细讲给你听】
背景是现在AI代理大多只做代码建议，比如GitHub Copilot，但Goose想干更脏的活——直接在你的机器上安装、执行、编辑和测试代码，不局限于编程，还能做研究、写作、自动化、数据分析。核心是它刚从block/goose仓库迁移到Linux基金会旗下的Agentic AI Foundation，这意味着项目有了中立治理，企业用起来更放心。关键细节：第一，用Rust写的，性能和跨平台兼容性好，支持macOS、Linux、Windows桌面应用和CLI。第二，支持15家以上模型提供商，包括Anthropic、OpenAI、Google、Ollama等，还能用你现有的Claude或ChatGPT订阅。第三，通过Model Context Protocol连接70多个扩展，这是个开放标准，意味着生态可插拔。影响是对于做企业级AI产品的你来说，这种开源、可定制、支持多种LLM的代理架构，直接对标你们平台需要的“决策智能代理”能力——客户工厂里的排产、调度、异常处理，理论上都能用这种代理去自动化。

Q-Fold：面向长视频理解的查询感知时空折叠方法
Q-Fold: Query-Aware Focus-Context Spatio-Temporal Folding for Long Video Understanding
arXiv · Biao Tang, Xu Chen, Shuxiang Gou, Jingyi Yuan, Yuhan Zhang, Chenqiang Gao · 昨天 14:19
⌄

【相关性评分】

【一句话讲清楚它在说啥】
这篇论文提出了一种叫Q-Fold的新方法，不用重新训练模型，就能让多模态大模型更高效地处理超长视频。它把视频切成片段，根据用户问题只保留关键片段的高清画面，其他片段压缩成带时间顺序的上下文布局，既省钱又提升效果。
【详细讲给你听】
背景是现在多模态大模型处理长视频时，几千帧画面全处理太贵，现有方法虽然会压缩帧数，但往往对所有保留的帧一视同仁，导致要么丢失细节要么丢失时间跨度。核心是Q-Fold这个零训练框架，它把视频按时间切成连续片段，然后根据用户的问题（比如“找出电池生产线上的异常”）做差异化处理：与问题相关的片段保留为高清的“焦点帧”，不相关的片段则折叠成保留时间顺序的上下文布局。关键细节有三个：一是实验在四个长视频基准上测试了多个多模态大模型，Q-Fold在不增加输入预算的情况下稳定提升性能；二是在超长视频基准上最高提升了9.1个百分点；三是代码会开源。机制上，这相当于给大模型配了一个智能剪辑师，先快速扫一遍视频，把重点片段高清保留，其他片段做成缩略图时间线，既保证关键证据不丢失，又让模型理解整个故事的时间顺序。这对做工业软件的你来说，意味着AI处理视频数据的能力又上了一个台阶，未来可能用来分析工厂监控视频、操作流程录像等长视频内容。
【关键术语小词典】
无特殊术语
【对你有啥用】
第一，这个“查询感知”的思路可以直接迁移到供应链排产场景。客户问“这批电池订单为什么延迟”，你的决策智能平台可以像Q-Fold一样，只聚焦排产计划中与延迟相关的工序和物料，把其他正常工序压缩成上下文，而不是全量计算。第二，你今年想突破AI Agent应用，Q-Fold的“零训练”框架是个启发——很多工业场景客户不愿意花时间重新训练模型，这种即插即用的优化方法更容易说服他们试点。第三，下次跟电池或钢铁客户聊视频监控分析时，可以提这个技术趋势：未来AI能更高效地处理工厂里24小时的生产录像，直接定位异常事件，这比传统逐帧分析快得多。

【背景知识】
多模态大模型处理长视频时，瓶颈在于计算成本——几千帧全量推理太贵，现有方法要么均匀采样丢细节，要么只保留关键帧丢时间连续性。Q-Fold的思路是“按需分配”：根据用户问题动态决定哪些片段保留高清细节，哪些压缩成带时间戳的缩略图布局，类似给模型配了个智能剪辑师。这种零训练框架的好处是即插即用，不用动模型本身，但局限也很明显——如果用户问题本身定义模糊（比如“看看有没有异常”），焦点片段的选择可能不准，影响效果。

【一句话讲清楚它在说啥】
这篇论文讲的是怎么用大模型和视觉模型搭一个能回答足球比赛视频问题的系统，拿了比赛第三名，核心思路是用多个专家模型分工合作。
【详细讲给你听】
背景是足球视频问答这个任务挺难，因为要同时理解画面、文字和比赛规则。之前的方法要么只靠单一模型，要么数据不够。这篇论文做了两件事。第一，他们搞了一个低成本的数据合成流程，用视觉语言模型自动把原始足球数据变成各种问答对，省了人工标注。第二，他们设计了一个叫MSUE的多专家架构，核心是用一个大语言模型当调度员，根据问题类型把任务分给三个专家：文本专家用Gemini3-Flash处理规则类问题，图像专家用微调过的Qwen3-VL分析画面细节，视频专家从外部知识库查历史数据。最终在测试集上准确率达到0.95，拿了第三名。关键细节是这种“调度+专家”的模式比单一模型灵活，而且数据合成方法可以迁移到其他领域。影响是这种架构思路对工业场景的多模态任务有参考价值，比如把不同传感器数据分给不同模型处理。
【关键术语小词典】
VQA：视觉问答，让AI根据图片或视频内容回答问题。VLM：视觉语言模型，能同时理解图像和文本的AI模型。MSUE：多模态足球理解专家，这篇论文提出的系统名字。Gemini3-Flash：谷歌的一个轻量级大语言模型。
【对你有啥用】
第一，这种“调度+多专家”的架构思路可以借鉴到你的决策智能平台里。比如供应链优化场景，可以针对不同子问题（排程、库存、物流）分别训练专家模型，再用一个调度器动态分配，比单一模型更灵活。第二，数据合成流程对你有直接启发。你平时跟客户沟通时，客户往往缺标注数据，这种用大模型自动生成训练数据的方法可以帮你快速验证产品假设，降低落地成本。第三，这个架构本质上是一个“路由”设计，跟AI Agent里的工具调用很像。你可以研究一下怎么把这种思路用到你的产品里，比如让LLM根据用户问题自动调用不同的算法模块，提升产品智能化程度。

OpenAI 为 Codex 智能体打造安全的 Windows 沙盒
InfoQ 中文 · 作者：Leela Kumili · 昨天 18:30
⌄
https://www.infoq.cn/article/P3C52z1QFIgM0oBSIiXO?utm_source=rss&utm_medium=article

【一句话讲清楚它在说啥】
OpenAI 给它的编程智能体 Codex 做了一个 Windows 专用沙盒，让代码在隔离环境里安全运行，防止 AI 生成的代码搞坏系统或泄露数据。
【详细讲给你听】
背景是现在 AI 编程助手越来越强，但企业客户最怕的是 AI 生成的代码乱跑，比如访问不该访问的文件、执行危险命令。之前 Codex 主要跑在云端 Linux 环境，但很多制造业客户用的是 Windows 系统，尤其是工控机、MES 终端。OpenAI 这次专门为 Windows 做了沙盒，本质是一个轻量级虚拟机，Codex 在里面执行代码、操作文件，但完全跟宿主机隔离。关键细节有三点：第一，沙盒支持文件系统重定向，AI 能读写指定文件夹，但碰不到系统目录；第二，网络访问默认关闭，需要显式授权才能联网，防止数据外泄；第三，沙盒可以一键重置，每次任务结束后环境自动销毁。这对工业软件场景特别重要，因为电池、钢铁这些工厂的 IT 环境非常封闭，安全合规是底线。说白了，OpenAI 在解决 AI 落地企业级场景的“最后一公里”问题——让客户敢用 AI 写代码、改配置、操作本地系统。
【关键术语小词典】
- Codex / 科德克斯：OpenAI 的 AI 编程智能体，能理解自然语言并生成、执行代码。
- 沙盒 / Sandbox：隔离的虚拟运行环境，让程序在里面跑但影响不到外部系统。
- MES / 制造执行系统：工厂里管理生产流程的软件，常跑在 Windows 工控机上。
【对你有啥用】
第一，你服务的制造业客户（电池、医药）对系统安全极其敏感，这个沙盒方案可以直接作为你推销 AI 决策平台时的“安全卖点”——跟客户讲，连代码执行都能隔离，数据更没问题。第二，你们平台如果要集成 AI 排程或优化算法，可以考虑借鉴这种“沙盒+一键重置”的架构，让客户放心在本地跑 AI 模型，而不是必须上云。第三，这改变了你对 AI Agent 落地边界的理解：之前觉得 Agent 只能做云端推理，现在看本地沙盒让 Agent 能直接操作工控机、修改排产参数，产品形态可以更“重”。

【详细讲给你听】
