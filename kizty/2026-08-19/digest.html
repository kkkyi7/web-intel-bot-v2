阿里开源的小模型 Qwen 3.8 27B 在第三方评测里拿到 52 分，跟 GPT-5.6 最高配置持平，只比两个超大模型低一分，说明小模型性能已经逼近巨头。
【详细讲给你听】
这事儿得从评测机构 Artificial Analysis 说起，他们搞了个智能指数，专门横向对比各家大模型的实际能力。以前这个榜单基本被 OpenAI、谷歌、DeepSeek 这些大参数模型霸榜，动辄几百 B 甚至上万亿参数。这次 Qwen 3.8 27B 直接拿了 52 分，什么概念呢，GPT-5.6 Luna 的最高配置也是 52 分，GLM-5.2 和 DeepSeek V4 Pro 也就比它高一分，但人家 GLM 是 753B 参数，DeepSeek 是 1.7T 参数，Qwen 只有 27B，差了三十倍到六十倍的规模。Luna 的参数量官方没公布，但按惯例肯定比 27B 大得多。这背后的意义在于，模型能力的天花板不再只靠堆参数，小模型通过更好的训练方法和数据质量，也能摸到第一梯队的边。对开发者来说，27B 意味着能跑在消费级显卡上，部署成本直线下降，私有化部署和边缘计算的可能性一下子打开了。对做企业服务的公司来说，客户最怕的就是数据安全和大模型成本，现在这个尺寸的模型能给出接近顶级的智能表现，整个商业逻辑都变了。

你做的决策智能平台如果要在客户现场私有化部署，以前得跟客户解释为什么必须用云端大模型，现在 Qwen 3.8 27B 这个成绩直接给了你谈判筹码，可以跟客户说开源小模型已经够用，数据不用出园区。另外你关注供应链排程算法，这类场景对延迟敏感且数据敏感，27B 级别模型跑在本地 GPU 上做实时决策支持，成本比调 API 低一个数量级，这个点下次跟制造业客户聊架构时可以主动提。最后，你今年想深化 AI Agent 方向，小模型性能逼近大模型意味着 Agent 的推理成本会大幅下降，多 Agent 协作的可行性变高了，你可以拿 Qwen 3.8 在本地跑一个多 Agent 排产模拟试试。

持续LLM改进的经验链方法
Chain-of-Experience for Continual LLM Improvement
arXiv · Haoqin Tu, Yunhao Fang, Yizhong Wang, Cihang Xie, Shen Yan · 昨天 17:22

【相关性评分】

【一句话讲清楚它在说啥】
这篇论文提出一种叫经验链的方法，让大模型在测试时通过反复试错和自我反馈持续变聪明，实验显示平均提升5.6%准确率，还省了19%的API成本，而且模型越强提升越明显。
【详细讲给你听】
这篇论文的核心问题是，现在评估大模型都是给个问题直接看答案，但人不是这么干事的，人会从经验里学。作者提出一个叫经验链的框架，让模型在推理时不断迭代，每轮根据反馈调整思路，形成持续改进的循环。反馈来源可以是模型自己反思，也可以是外部信号比如代码跑测试的通过率。他们用8个模型在数学、编程、知识问答上做了实验，包括GPT-5、Gemini-2.5 Pro、Claude-4.5 Sonnet这些顶级模型。结果很明确，只要有迭代经验就比一次性回答强，光靠自我反馈就有明显提升，整体准确率涨了5.6%，API成本反而降了19%。有意思的是，把不同反馈渠道组合起来效果更好，比如模型自我反思加正确性信号。还有个关键发现，模型基础能力越强，通过经验链提升的幅度越大，而且就算反馈信号很弱甚至有点误导，模型也不会崩。另外大部分提升在头几轮迭代就出现了，说明不需要无限循环就能见效。这对做AI产品的人来说，意味着推理时多给模型几次机会，可能比换更大模型更划算。
【关键术语小词典】
Chain-of-Experience / 经验链：让模型在测试时通过多轮交互反馈持续改进的推理方法
Test-time compute / 测试时计算：模型在回答问题阶段额外消耗的计算资源，而非训练阶段
Self-feedback / 自我反馈：模型自己审视自己的输出并修正错误的能力
API cost / API调用成本：使用模型服务时按token或请求次数计算的费用
【对你有啥用】
第一，你做的决策智能平台本质上是帮客户做优化决策，这个思路可以直接借鉴到排产算法里，与其追求一次性给出最优解，不如设计一个多轮方案推演机制，让算法根据约束反馈逐步收敛，跟客户聊的时候可以提这个技术趋势作为产品差异点。第二，这篇论文的结论说模型基础能力越强提升越明显，这改变了你对模型选型的判断，在给客户设计方案时，与其纠结用哪个模型，不如在推理链路上做文章，用迭代反馈机制来弥补单次推理的不足。第三，19%的API成本下降这个数字很关键，你在跟客户算ROI的时候可以直接引用，说明智能决策系统不是越贵越好，合理的推理策略设计能同时提升效果和降低成本。

【背景知识】
这篇论文讨论的是测试时计算（test-time compute）的另一种玩法：不是靠加大推理预算或换更强模型，而是让模型在回答前先自己试错几轮，把反馈（自我反思或外部信号如代码执行结果）喂回给模型，形成迭代改进。这个方向和今年流行的Agent/工具调用范式有交叉，但更聚焦在单次推理链路内的自我修正，而不是外部编排。要注意的是，它的收益在简单任务上可能不明显，且依赖模型本身具备一定的自我评估能力，弱模型可能改进有限。
【社区讨论】
社区讨论多集中在对比CoT（思维链）和CoE（经验链）的差异，有人认为CoE更接近人类试错学习，也有人质疑多轮迭代的延迟和成本在真实产品中是否可控。

背景是这轮内存涨价不是普通的市场波动，而是从2025年下半年开始持续一整年的供需失衡。HackerNews上这篇帖子引用了Tom's Hardware的数据，128GB DDR5内存条从历史最低价到现在涨了整整10倍，12个月内涨幅500%。这已经不是简单的周期性波动，而是结构性变化。

代理推荐系统中的委托不对称性
Delegation Asymmetry in Agentic Recommender Systems: Measuring Two-Sided Receptivity in Online Dating
arXiv · Daria Leshchikova, Valentina V. Kuskova, Dmitry Zaytsev, Valerii Klimov · 昨天 17:51
⌄
http://arxiv.org/abs/2608.18058v1
【相关性评分】

【一句话讲清楚它在说啥】
这篇论文研究的是在约会平台上，用户愿意让AI替自己聊天，但不太愿意跟别人的AI聊天。作者通过大规模调查发现，这种“委托”和“接收”的不对称性，会严重影响AI代理在匹配平台上的实际效果。
【详细讲给你听】
这篇论文来自arXiv，研究的是AI代理在匹配平台（比如约会软件）上的一个核心问题：用户愿意把聊天交给AI，但愿意接受别人用AI跟自己聊吗？作者对某大型约会平台的活跃用户做了两次大规模调查，样本量分别是2894人和2617人，覆盖两种语言。他们用统计模型分析发现，用户“愿意派AI出去”和“愿意接收AI消息”是两个不同的心理维度，虽然高度相关（相关系数0.92），但确实可以分开测量。关键发现是：用户部署自己AI的门槛远低于接收别人AI的门槛，前者阈值是-0.38，后者是+0.32，完全投入接收则需要+1.39。换句话说，大家更愿意让自己的AI去“代聊”，但不太愿意跟别人的AI“对话”。在随机配对模拟中，只有4%到13%的配对能同时满足一方部署AI、另一方愿意接收。作者还做了设计模拟：如果强制要求“你愿意接收别人的AI，才能部署自己的AI”，互动量会砍掉一半以上；但如果根据用户的接收意愿来路由AI消息，每次接触的互动率能提升三倍，而且这个效果在样本外验证中依然稳健（AUC 0.88）。这篇论文对AI代理在推荐系统、社交平台的设计有直接启示，尤其是关于披露机制、选择加入（opt-in）机制和“接收意愿感知”的匹配算法。
【关键术语小词典】
- Agentic Recommender System / 代理推荐系统：让AI代理替用户做决策或交互的推荐系统。
- Receptivity / 接收意愿：用户愿意接受来自AI代理的沟通或交互的程度。
- Latent-variable measurement model / 潜变量测量模型：用统计方法测量不可直接观察的心理特质。
