【一句话讲清楚它在说啥】
Andrej Karpathy 吐槽 LLM 写代码时爱瞎猜、过度设计、乱改无关代码。有人把他的观察总结成一个 CLAUDE.md 文件，让 Claude 写代码时先思考、保持简单、只改该改的地方、用测试验证结果。
【详细讲给你听】
背景是 AI 大佬 Andrej Karpathy 发帖指出 LLM 写代码的几个致命毛病：模型会替你做错误假设然后直接执行，不检查、不澄清、不展示权衡；特别喜欢把代码搞复杂，100 行能解决的问题非要写 1000 行；还会顺手改掉或删掉它没完全理解的注释和代码。这些痛点对任何用 AI 写代码的产品经理和开发者来说都太真实了。

核心是这个叫 Multica 的开源项目，它把 Karpathy 的观察提炼成一个 CLAUDE.md 文件，专门用来改善 Claude Code 的行为。文件里定义了四条原则：先思考再编码、简单优先、外科手术式修改、目标驱动执行。每条原则都对应具体的行为约束，比如“不要假设，不确定就问”、“不要为单次使用场景写抽象层”、“只改你被要求改的地方”、“把‘加验证’变成‘先写测试让失败，再让测试通过’”。

关键细节是它把模糊指令转化为可验证的目标，比如把“修复 bug”转化为“先写一个能复现 bug 的测试，再让它通过”。这种思路对工业软件里的排程算法调试、供应链优化规则验证有直接借鉴意义。

影响是给所有用 AI 写代码的人一个可落地的行为规范模板。对于做决策智能平台的人来说，这意味着可以把类似的“先验证再执行”逻辑嵌入到 AI Agent 的产品设计中，让模型在生成排程方案前先检查约束条件、展示权衡。
【关键术语小词典】
- CLAUDE.md / 克劳德配置文件：放在项目根目录的文本文件，用来定义 Claude Code 的行为规则和编码风格。
- Multica / 穆尔提卡：一个开源平台，用于运行和管理带可复用技能的编码 Agent。
- Andrej Karpathy / 安德烈·卡帕西：前 OpenAI 和特斯拉 AI 负责人，以对 LLM 的深刻观察著称。
【对你有啥用】
第一，你正在做决策智能平台，这个“先验证再执行”的思路可以直接搬到排程算法里。下次跟客户聊时可以说：“我们的 AI 不会直接给方案，而是先展示假设和权衡，确认后再生成排程结果。”这能解决制造业客户对 AI 黑箱的信任问题。

第二，你关注 AI Agent 产品落地，这个 CLAUDE.md 文件本身就是 Agent 行为规范的优秀产品案例。你可以借鉴它的原则，在你自己的平台上设计“Agent 行为配置文件”，让用户自定义 AI 的决策风格——是激进优化还是保守安全。

第三，你今年想深化工业软件 + AI 的产品理解，这个“外科手术式修改”原则特别适合工业场景。工业软件里改一个参数可能影响整条产线，AI 必须学会“只改该改的，不动不该动的”。你可以把这个原则写进产品需求文档，作为 AI 模块的核心约束。
