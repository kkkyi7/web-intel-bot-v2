YC 总裁 Garry Tan 开源了他个人的 Claude Code 工作流 gstack，包含 23 个角色工具，让他一个人用 AI 就能完成 CEO、设计师、工程经理等整个团队的工作，2026 年他的代码产出效率是 2013 年的 810 倍。

背景是 AI 编程工具已经让个人开发者能完成过去整个团队的工作。Andrej Karpathy 在播客里说从去年 12 月就没怎么手写过代码了，Peter Steinberger 一个人用 AI Agent 做出了 24.7 万星的开源项目。Garry Tan 作为 YC 总裁，过去 60 天里兼职做了 3 个生产服务和 40 多个功能。核心是他开源了 gstack 这个工具集，把 Claude Code 变成一个虚拟工程团队：有 CEO 角色重新思考产品、工程经理锁定架构、设计师检查 AI 生成的垃圾、QA 打开真实浏览器测试、安全官跑 OWASP 审计、发布工程师自动发 PR。总共 23 个专家角色加 8 个强力工具，全部是斜杠命令和 Markdown 格式。关键数据：2026 年到 4 月 18 日，他的逻辑代码产出已经是 2013 年全年的 240 倍。他特意说明这不是原始代码行数膨胀，而是经过通胀调整后的真实效率提升。这个工具完全免费，MIT 协议开源。

PPT Master：AI 从文档生成可编辑的 PPTX

【一句话讲清楚它在说啥】
这是一个开源工具，能把你扔给它的任何文档（Word、PDF、网页等）自动生成一份原生可编辑的 PowerPoint 文件，包括形状、动画、演讲者备注，甚至还能把备注转成语音旁白。
【详细讲给你听】
背景是，市面上大多数“AI 生成 PPT”的工具，要么只输出一张不能编辑的图片，要么生成的是死板的模板，你没法后续调整。这个项目叫 PPT Master，由 Hugo He 开发并开源在 GitHub 上。核心功能是：你上传一个文档，它调用 AI 模型（比如 Claude、GPT）理解内容，然后直接生成一份真正的 .pptx 文件——里面的每个文本框、形状、图表都是原生 PowerPoint 对象，你可以双击编辑、改字体、调颜色。关键细节有三点：第一，它支持你自定义自己的 .pptx 模板，公司品牌色、Logo 都能自动套用，这对做企业级方案演示非常实用。第二，它能把演讲者备注转成音频旁白，播放 PPT 时每页自动朗读，适合做自动化培训材料或客户提案。第三，作者明确说“这是一个工具，不是许愿池”，意思是它帮你完成 80% 的苦活，剩下 20% 的打磨需要你自己动手，因为可编辑的 PPTX 就是为了让你继续改，而不是一张死图。影响上，这个工具降低了从文档到演示文稿的转换门槛，尤其适合需要频繁出方案、做汇报的产品经理和顾问。
【关键术语小词典】
PPTX：Microsoft PowerPoint 的原生文件格式，支持编辑形状、动画、图表等。无特殊术语。
【对你有啥用】
第一，你作为工业软件 PM，经常要给客户做方案演示或内部汇报，这个工具能把你手头的技术文档、调研报告直接转成可编辑的 PPT，省掉手动排版的时间，让你更聚焦在内容逻辑和客户沟通上。第二，它支持自定义模板，你可以把公司决策智能平台的品牌模板套进去，生成统一的对外材料，提升专业度。第三，这个项目本身是 AI Agent 在文档处理领域的典型落地——输入文档、调用 LLM、输出结构化文件，你可以研究它的技术架构，看看能不能借鉴到你的供应链排程产品里，比如把客户的工艺文档自动转成排产参数配置表。

市面上大多数AI生成PPT的工具（比如Gamma、Tome）输出的是网页版或图片，没法在PowerPoint里直接编辑。这个项目底层用python-pptx库操作.pptx文件结构，所以生成的每个文本框、形状都是原生对象，能双击改内容。不过python-pptx本身对复杂动画和旧版.ppt格式支持有限，遇到特别花哨的模板可能得手动修。

这篇论文提出用大模型模仿老人的说话风格和模式，构建一个“语言数字孪生”，用来早期检测认知障碍，效果比直接用GPT好。

背景是数字孪生在医疗里越来越火，但之前主要用在生理数据上。对于认知健康，早期发现轻度认知障碍很难，而语言模式是一个非侵入性的生物标志物。核心是作者用大模型，结合个人语言风格和上下文信息，给每个老人建一个“语言双胞胎”。关键细节有三：一是他们用了多头的条件变分自编码器来同时衡量生成文本的质量和预测认知分数；二是在I-CONECT数据集上，这个数字孪生能保留个人特征，重建误差和MoCA认知评分预测误差跟真实数据差不多；三是比直接用GPT生成的回答效果好。说白了，这就相当于给每个老人定制了一个“AI版自己”，通过聊天就能持续监控认知状态，比定期去医院做测试方便得多。
【关键术语小词典】
- Digital Twin / 数字孪生：在虚拟世界创建一个实体的数字副本，用于模拟和预测。
- MCI / 轻度认知障碍：介于正常衰老和痴呆之间的状态，是早期干预的关键窗口。
- MoCA / 蒙特利尔认知评估：一种常用的认知功能筛查量表。
- cVAE / 条件变分自编码器：一种生成模型，能学习数据分布并生成新样本，这里加了条件来控制生成。
【对你有啥用】
第一，这个思路对你做供应链排程算法有直接启发。排程本质上也是在做“行为预测”，你可以思考：能不能用类似方法，给每个产线、每个设备建一个“排程数字孪生”？通过历史排产数据学习其“行为模式”，然后预测瓶颈。第二，跟客户聊“AI+工业”时，你可以用这个案例说明“个性化模型”的价值。客户往往觉得AI是黑盒，但数字孪生是“可解释的镜像”，这能降低信任门槛。第三，你关注AI Agent，这个框架本质上就是一个“认知监控Agent”，它把大模型从通用对话变成了“特定个体的行为模拟器”，这对你做产品设计很有参考价值。

自回归玻尔兹曼生成器
Autoregressive Boltzmann Generators

【一句话讲清楚它在说啥】
这篇论文提出一种叫自回归玻尔兹曼生成器的新方法，用类似大语言模型的架构来模拟分子系统，比传统方法更快更准，还能在推理时动态调整。
【详细讲给你听】
背景是统计物理里有个老大难问题：怎么高效地从分子系统的热力学平衡态里采样。传统方法慢，而且样本之间高度相关。之前有人搞出玻尔兹曼生成器，用生成模型加重要性采样来快速生成独立样本，但主流方案依赖标准化流。标准化流有两个硬伤：要么因为严格可逆约束导致表达能力有限，要么计算似然函数太贵。这篇论文直接跳出流模型框架，用自回归建模来做。核心创新是把分子构象生成当成一个序列预测问题，类似大语言模型逐字生成句子。他们搞了个叫Robin的模型，1.32亿参数，在8残基肽系统上把零样本能量误差降低了超过60%。关键细节是自回归架构允许在推理时做顺序干预，比如固定某个原子位置再生成其余部分，这对工业场景里的约束优化很有用。影响是给分子模拟和药物设计提供了一个更灵活、可扩展的新工具，而且直接借用了LLM领域成熟的架构经验。
【关键术语小词典】
玻尔兹曼生成器：用生成模型快速采样分子平衡态的方法。标准化流：一种可逆的生成模型，要求变换是一一对应的。零样本能量误差：模型没针对特定系统训练时，预测能量和真实能量的差距。
【对你有啥用】
第一，这个思路可以迁移到供应链排程优化里。排产算法经常要处理大量约束和顺序决策，自回归模型天然适合这种逐步生成解的模式，比传统启发式或流模型更灵活。第二，论文提到Robin借用了LLM架构，这提示你在工业软件里可以复用Transformer和注意力机制来处理时序生产数据，比如订单序列、设备状态序列。第三，下次和制药或化工客户聊AI应用时，可以提这个方向作为技术储备，展示你对前沿分子模拟的了解，能增加技术信任感。

像玩剧本杀一样，玩好 Agentic AI
InfoQ 中文 · 陈姚戈 · 2 天前

【一句话讲清楚它在说啥】
这篇文章用剧本杀比喻，讲怎么设计和管理多个 AI Agent 协作完成任务，核心是给每个 Agent 分配角色、目标和规则，避免它们乱跑或打架，最终稳定产出结果。
【详细讲给你听】
背景是现在 AI Agent 很火，但很多团队发现让多个 Agent 一起干活时容易失控，比如互相抢任务、重复劳动或者偏离目标。作者提出一个类比：把 Agent 系统当成一场剧本杀。剧本杀里每个玩家有固定角色、背景故事和任务目标，大家按规则推进剧情，而不是自由发挥。核心观点是，设计 Agentic AI 系统时，不能只给 Agent 一个“通用大脑”，而要像写剧本一样，为每个 Agent 定义清晰的“角色卡”（职责范围）、“目标卡”（要达成的结果）和“规则卡”（交互协议和边界）。关键细节包括：1）作者强调“角色卡”要具体到能做什么、不能做什么，比如一个 Agent 只负责数据清洗，另一个只负责生成报告，不能越界。2）提到“剧本”本身要包含容错机制，比如某个 Agent 卡住了，系统要有预案，就像剧本杀里主持人可以临时调整规则。3）影响是，这种设计思路让 AI 系统从“黑盒”变成“可编排”的，对开发者来说，降低了调试和迭代的复杂度，对产品经理来说，更容易跟客户解释系统的行为逻辑。
【关键术语小词典】
- Agentic AI / 智能体 AI：指能自主感知环境、做决策并执行任务的 AI 系统，不是单次问答。
- 角色卡 / 目标卡 / 规则卡：作者提出的设计框架，分别定义 Agent 的职责、目标和交互边界。
【对你有啥用】
1. 你正在做决策智能平台，这个“角色卡”思路可以直接用在供应链排程算法里。给每个排程 Agent 分配清晰的角色（比如一个负责物料约束、一个负责设备约束），比用一个通用模型去优化整个链条更可控，也更容易跟客户解释为什么某个排程结果合理。下次跟电池或钢铁客户聊时，可以用“剧本杀”这个比喻，降低沟通成本。
2. 你关注 AI Agent 落地，这篇文章点出了一个常见坑：多 Agent 协作不是“堆模型”，而是“定规则”。你在设计产品时，可以借鉴这个框架，在平台里预置“角色模板”和“规则模板”，让客户像搭积木一样配置自己的 Agent 系统，这能提升产品的易用性和差异化。
3. 对个人学习路径来说，这篇文章提示你：研究 Agent 时，别只盯着 LLM 本身，要多看“系统设计”和“交互协议”方面的资料。比如可以搜一下“Multi-Agent Orchestration”或“Agent Workflow Design”，这些才是工业软件里真正能落地的部分。

【背景知识】
多 Agent 系统在实际落地时，最大的坑不是模型能力不够，而是 Agent 之间缺乏清晰的职责边界和协作规则，容易变成“一群聪明人各干各的”甚至互相干扰。这篇文章用剧本杀的角色卡、目标卡、规则卡来类比，本质上是在讲一种结构化编排思路——把每个 Agent 当成一个“有固定剧本的演员”，而不是一个万能助手。这种思路在工业软件里很实用，比如排程场景中，物料约束 Agent、设备约束 Agent、订单优先级 Agent 各司其职，比用一个通用大模型去端到端优化更可控、更可解释。不过要注意，这种强规则设计也有局限：当业务规则频繁变动时，维护“剧本”的成本会上升，且对突发异常场景的适应性不如纯端到端方案。
【社区讨论】

【详细讲给你听】
背景是这两年开源生态里频繁出现“供应链投毒”事件——黑客先攻破一个流行插件的开发者账号，然后推送一个带后门的更新版本，用户一自动更新就中招。VS Code 插件市场有几万个扩展，用户量巨大，一旦某个核心插件被污染，影响面会非常广。这次 VS Code 1.123 版本引入的“两小时缓冲期”机制，核心逻辑很简单：插件作者发布新版本后，不会立刻推送到所有用户，而是先在微软服务器上“冷置”两小时。在这两小时内，如果安全团队或社区发现异常，可以紧急下架该版本，阻断攻击扩散。关键细节有三个：第一，这个缓冲只针对自动更新，用户手动点“立即更新”不受限制，给高级用户留了自主权。第二，微软同时强化了插件签名验证，要求所有新版本必须用硬件安全密钥签名，防止身份伪造。第三，这个机制借鉴了 Google Chrome 扩展商店的类似做法，但 VS Code 作为开发工具，风险更高——因为插件能直接访问文件系统和终端。对开发者来说，这意味着以后自动更新会更安全，但紧急修复补丁的推送速度会慢两小时，算是一种“安全 vs 敏捷”的权衡。
【关键术语小词典】
- Supply Chain Attack / 供应链攻击：攻击者通过污染软件依赖链中的某个环节，间接攻击最终用户。
- VS Code / Visual Studio Code：微软开发的免费代码编辑器，全球最流行的开发者工具之一。
- 插件签名验证：用数字证书确认插件发布者身份，防止冒名发布恶意版本。
【对你有啥用】
第一，你做的决策智能平台如果涉及“插件市场”或“算法模型市场”功能，这个两小时缓冲机制可以直接借鉴——给客户一个“安全发布窗口”，能显著降低客户对第三方组件安全性的担忧。第二，跟制造业客户（尤其是电池、医药行业）聊供应链安全时，可以拿这个案例说明“软件供应链攻击”离工业软件很近——如果你们的排程算法依赖某个第三方优化库，一旦被投毒，整个产线都会停摆。第三，作为 PM，你可以把这个机制写进产品需求文档的“安全特性”部分，作为竞品分析的一个亮点，提升产品在军工、医药等强监管行业的可信度。
