别分类，让模型瞎编
Don't classify. Hallucinate!
Simon Willison · 3 天前

【一句话讲清楚它在说啥】
给博客打标签时，与其让 LLM 从上千个现有标签里选，不如让它自由发挥编新标签，再用向量相似度匹配到最接近的已有标签，又快又准。
【详细讲给你听】
Simon Willison 的博客有 1856 个标签，数量太多，没法一次性塞给 LLM 让它做多标签分类。传统做法是给模型一个候选标签列表让它挑，但标签一多，上下文窗口装不下，效果也差。Doug Turnbull 提了个反直觉的思路：别让模型分类，让它直接“幻觉”出标签。具体做法是，告诉模型“你想一个最合适的分类名”，不提供任何现有词表，模型自由输出它认为合理的标签。然后把这些“幻觉标签”转成向量，跟现有 1856 个标签的向量库做相似度检索，取最接近的几个作为最终标签。关键在于，提示词里要给出标签的形状示例，比如“Furniture / Living Room Furniture / Coffee Tables”这种层级结构，模型就能猜出你想要的粒度。这个方法的妙处在于，把“分类”这个约束问题变成了“生成+检索”两段式，既绕开了上下文长度限制，又利用了向量检索的精确匹配能力。对做产品的人来说，这是个典型的“换个角度拆问题”的案例。
【关键术语小词典】
LLM：大语言模型，能理解和生成自然语言的 AI 系统。
Vector Embeddings：向量嵌入，把文本转成数字数组，语义相近的文本向量距离也近。
Tagging：标签化，给内容打上分类标签便于检索和管理。
Doug Turnbull：搜索引擎专家，提出“幻觉标签+向量匹配”方案的人。
【对你有啥用】
第一，你做的决策智能平台里，如果客户有大量历史数据需要打标或归类，这个“生成+检索”两段式思路可以直接用在产品设计里，比硬让模型做多分类靠谱得多。第二，跟客户聊供应链优化时，可以拿这个例子说明“不要用 AI 硬解约束问题，先拆成生成和匹配两步”，这种讲法比讲算法细节更容易让客户听懂。第三，你自己写博客或整理文档时，可以试试这个流程：让 Claude 自由生成标签，再用向量库匹配，比手动分类省力得多。

【背景知识】
传统上让 LLM 做分类任务需要把候选标签列表塞进上下文，但标签数量一大（比如上千个）就会超出上下文窗口，而且模型在超长列表里选容易出错。Doug Turnbull 提出的思路是反过来：先让模型自由生成它认为合理的标签（即'幻觉'），再把生成的标签转成向量，和已有标签的向量库做相似度检索，匹配到最接近的真实标签。这个'生成+检索'两段式方法绕开了上下文长度限制，也利用了向量检索的语义匹配能力。不过它依赖向量库的质量和阈值设定，如果标签语义太接近或向量模型不够好，匹配结果可能不准。
【社区讨论】
Simon Willison 在博客里转发了这个技巧，评论区有讨论认为这本质上是把'分类'问题转成'生成+检索'问题，也有人提到类似思路在 RAG 里用于假设性文档嵌入（HyDE），但要注意幻觉标签可能引入噪声，需要设置合适的相似度阈值。

【详细讲给你听】
背景是 Anthropic 最近在官方平台文档里放出了 Claude 各版本的系统提示词全文。系统提示词就是藏在模型背后、定义它性格和行为规则的那段指令，以前大家只能靠猜测或逆向工程去推断。这次官方直接公开，等于把底牌亮出来了。Simon Willison 这个老牌开发者把每次版本更新的提示词差异整理成了 git 提交历史，方便对比。最值得注意的几个点：一是 Opus 4.8 到 Opus 5 的 diff 里出现了 Claude Fable 5 和 Claude Mythos 5 这两个新模型名，说明 Anthropic 内部产品线比公开的更丰富。二是提示词里新增了广告相关规则，要求讨论时统一用 Claude products 而不是 Claude，说明商业化在加速。三是有人吐槽提示词太长，和主流观点建议的越短越好相悖，但 Anthropic 显然认为详细规则能更好约束模型行为。四是提示词里明确写了如果用户说图片存在但实际没上传，模型要自己检查，这种常识性规则也要写进系统提示词，说明 Anthropic 对模型自主判断能力还是不放心。
