【一句话讲清楚它在说啥】
一个开源工具，让AI编程助手（如Claude Code、Cursor）能记住你之前项目的架构、偏好和bug修复，下次对话不用再重复解释。基于Karpathy的LLM Wiki模式，加了置信度评分、知识图谱和混合搜索。
【详细讲给你听】
背景：现在用AI编程助手最大的痛点就是每次新会话它都“失忆”。你明明在Session 1配置了JWT认证，Session 2问限流时它又不知道你的认证方案。内置的CLAUDE.md最多只能写200行，还容易过时。核心：agentmemory是一个独立的记忆服务器，通过12个钩子自动捕获你的编码行为，压缩成可搜索的记忆，下次会话自动注入相关上下文。关键细节：1）在LongMemEval-S基准测试（500个问题）上，R@5检索准确率达95.2%，远超BM25的86.2%。2）用agentmemory每年token成本约10美元，而用LLM摘要要500美元，全量粘贴则直接超出上下文窗口。3）支持所有主流代理：Claude Code、Cursor、Gemini CLI、Codex CLI等，通过MCP或REST API共享同一个记忆服务器。4）记忆有生命周期管理：四层合并+衰减+自动遗忘，不会无限膨胀。影响：这本质上解决了AI编程助手“一次性对话”的根本缺陷。对开发者来说，意味着可以真正积累项目知识库，代理从“每次从零开始”变成“持续学习”。对产品经理来说，这是AI Agent从玩具走向生产力的关键基础设施。
【关键术语小词典】
- MCP / Model Context Protocol：模型上下文协议，让AI代理与外部工具/数据交互的标准接口
- R@5 / Recall at 5：检索前5个结果中包含正确答案的比例，衡量记忆系统找东西准不准
- LongMemEval-S：ICLR 2025提出的长期记忆评估基准，包含500个需要跨会话记忆的问题
- Karpathy's LLM Wiki模式：Andrej Karpathy提出的让LLM维护一个持续更新的知识库文件的方法
【对你有啥用】
1. 产品判断：你做的决策智能平台，客户最头疼的就是每次排产优化都要重新输入工艺参数和约束条件。agentmemory这种“跨会话持久记忆”的思路，完全可以搬到供应链优化场景——让AI排程助手记住每个工厂的设备特性、物料清单和客户偏好，下次排产直接复用。这能大幅降低客户的上手成本。

2. 客户沟通：下次跟电池或钢铁客户聊时，可以拿这个做类比：“就像AI编程助手现在能记住你的代码架构，我们的决策智能平台也能记住你们工厂的排产规则和历史优化方案，不用每次重新教。”这种“记忆即生产力”的叙事，比讲算法精度更容易让业务方理解价值。

3. 学习路径：你今年想深化AI Agent理解，这个项目是绝佳的学习样本。它把Karpathy的LLM Wiki模式工程化了，加了置信度评分、知识图谱、混合搜索这些工业级组件。建议你跑一遍它的benchmark代码，理解它怎么评估记忆质量——这对你评估AI产品的效果指标很有参考价值。

【详细讲给你听】
背景是现在编码智能体（如 Claude Code、Cursor）虽然能写代码，但经常一上来就瞎写，缺乏项目整体视角。这个项目创始人 Jesse 发现这个问题，于是搞了一套“超能力”框架。核心机制是：当你启动编码智能体时，它不会直接写代码，而是先退一步问你要做什么，把需求拆成你能消化的小块规格让你确认，然后生成一个实现计划——计划清晰到“一个热情但品味差、没判断力、没项目上下文、还讨厌测试的初级工程师都能照着干”。计划强调真正的红绿 TDD（测试驱动开发）、YAGNI（你不会需要它）和 DRY（不要重复自己）。你点头后，它启动子智能体驱动开发流程，让多个智能体分工处理工程任务，互相检查和审查代码。关键细节是：Claude 能自主工作长达两小时不偏离计划。这个框架已经集成到 Claude Code、Codex CLI、Cursor、GitHub Copilot CLI 等主流工具，安装方式各有不同，但核心技能会自动触发。
【关键术语小词典】
TDD / 测试驱动开发：先写测试再写代码，确保代码通过测试的开发方法。YAGNI / 你不会需要它：只写当前需要的代码，不提前写未来可能需要的功能。DRY / 不要重复自己：避免代码重复，把共同逻辑抽象成可复用模块。
【对你有啥用】
第一，这个方法论直接可以迁移到你做的排程算法产品里：让智能体先出规格再执行，能大幅减少客户沟通中“需求没对齐就开干”的坑，下次跟电池或医药客户聊排产优化时，可以拿这个框架当案例，说“我们让 AI 先理解你的排产规则再出方案”。第二，作为 PM，你可以把这个框架当作产品设计参考：它把“需求澄清-规格确认-计划生成-分步执行”拆成了可组合的技能模块，这种思路能帮你优化决策智能平台的产品流程，比如让用户先定义优化目标再跑算法。第三，它改变了你对编码智能体能力的认知——之前你可能觉得 AI 写代码就是生成片段，现在它展示了 AI 能自主管理完整开发流程，这对你评估 AI Agent 在工业软件中的应用深度很有启发。

【一句话讲清楚它在说啥】
Anthropic 把 Claude 模型打包成一套完整平台，直接部署在 AWS 上，让企业客户能在自己云环境里安全调用、微调和部署 Claude，不用再自己折腾底层基础设施。
【详细讲给你听】
背景是很多企业想用 Claude 但又担心数据安全、合规和运维成本，之前要么走 Anthropic 的公共 API，要么自己搭一套很重的推理环境。这次 Anthropic 和 AWS 深度合作，直接把 Claude Platform 做成 AWS 上的托管服务。核心变化是：企业可以在 AWS 账户里一键拉起 Claude 模型，数据不出云，还能跟 AWS 的 S3、Lambda、Bedrock 等原生服务无缝集成。关键细节有三个：第一，支持私有化部署，模型权重和客户数据都留在客户自己的 VPC 里，这对制造业客户（比如电池、钢铁）的敏感工艺数据非常关键。第二，提供了微调接口，企业可以用自己的生产排程、供应链历史数据来调优模型。第三，计费模式跟 AWS 其他服务一致，按实际用量付费，不用预购 license。影响是：以前工业软件公司想用大模型做决策智能，得自己搞 MLOps 团队，现在可以直接在 AWS 上像搭积木一样用 Claude，大幅降低 AI 落地门槛。对开发者来说，这意味着可以更快地做 PoC，不用纠结 GPU 资源调度。
【关键术语小词典】
- Claude Platform / Claude 平台：Anthropic 推出的企业级 AI 服务平台，包含模型、工具链和部署环境。
- AWS / 亚马逊云服务：亚马逊的云计算平台，提供计算、存储、AI 等基础设施服务。
- VPC / 虚拟私有云：AWS 上的隔离网络环境，客户数据不出这个网络，保证安全。
- PoC / 概念验证：小规模测试项目，验证技术方案是否可行。
【对你有啥用】
第一，你正在做工业软件 + AI 的产品落地，这个平台直接解决了客户最头疼的数据安全问题。下次跟电池或医药客户聊排程优化时，可以明确告诉他们 Claude 可以部署在 AWS 的私有 VPC 里，工艺配方数据不会外泄，这能打消合规顾虑。第二，你关注 AI Agent 和 LLM 应用，Claude Platform 的微调接口意味着你可以用自己客户的排产历史数据来定制模型，而不是用通用大模型做模糊建议。这能提升产品在供应链场景中的准确率。第三，作为 PM，你可以把这个平台当成一个“基础设施层”来思考：你的决策智能平台如果基于 Claude Platform 构建，就能省掉自建推理集群的成本，把精力集中在业务逻辑和算法优化上，这对产品迭代速度是直接加分。

之前企业用 Claude 主要走 Anthropic 公共 API 或自己搭推理环境，前者有数据外泄风险，后者运维成本高。这次 Claude Platform on AWS 相当于把 Anthropic 的模型、API、Agent 工具链直接做成 AWS 托管服务，企业可以在自己 AWS 账户里一键拉起，数据留在 VPC 内，还能跟 S3、Lambda 这些原生服务打通。注意它跟 Bedrock 上调用 Claude 的区别：这个平台给的是 Anthropic 原生的控制台和最新功能（比如 Agent Skills、代码执行），而 Bedrock 是 AWS 统一封装的多模型入口，两者面向的场景和灵活性不太一样。
