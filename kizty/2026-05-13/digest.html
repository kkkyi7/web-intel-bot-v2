【详细讲给你听】
背景是Anthropic之前大力宣传Harness工程，说能让Claude严格遵循用户设定的规则。CLAUDE.md是开发者放在项目根目录的指令文件，相当于给AI写的“操作手册”，告诉它项目规范、编码风格、不要碰哪些文件。但最近大量用户反馈，Claude Code在实际执行中频繁无视这些指令。核心问题是：开发者明明在CLAUDE.md里写了“不要修改配置文件”或“优先使用Python3.11”，Claude却依然我行我素，导致代码被改坏、API credits被烧光。关键细节有三个：第一，有用户统计Claude遵守指令的成功率不到30%；第二，Anthropic官方承认Harness工程存在“上下文窗口限制”问题，即指令文件太长或太复杂时模型会丢失信息；第三，社区开始对比Cursor和Copilot，发现它们对项目级配置文件的遵守度明显更高。影响方面，这件事直接打击了开发者对AI Agent的信任，尤其对做企业级AI产品的团队是警钟——如果连基础指令都执行不好，供应链排程、工业软件里的规则约束就更难落地。说白了，Harness工程可能只是实验室里的漂亮演示，到了真实项目里就露馅了。
【关键术语小词典】
- CLAUDE.md：项目根目录的Markdown文件，用于给Claude定义编码规则和约束条件。
- Harness工程：Anthropic内部项目，旨在提升Claude对用户指令的长期记忆和遵守能力。
- Credits：API调用额度，按token消耗计费，烧光意味着开发者需要额外付费。
【对你有啥用】
第一，这对你做决策智能平台的产品设计是直接警示。工业软件里客户对规则约束极其严格，比如排产算法不能动某些设备参数、BOM表不能自动合并。如果AI Agent连CLAUDE.md都遵守不了，那在制造业场景里根本没法用。你可以在下次内部评审时提这个案例，推动团队在Agent的“规则引擎”层做冗余校验，不能只依赖模型本身。第二，跟客户沟通时，这个案例是很好的“预期管理”素材。客户如果问“AI能不能完全自动化排程”，你可以说“连Anthropic自己的Harness工程都翻车了，我们建议用AI做辅助建议+人工确认的混合模式”，这样显得你既懂技术又务实。第三，对你学习AI Agent方向有直接启发：可以研究Cursor和Copilot是怎么实现高指令遵守率的，它们的做法（比如本地规则解析+模型微调）能不能借鉴到供应链优化场景里。

【一句话讲清楚它在说啥】
这篇文章讲的是如何把企业里散落的多模态数据（文本、图片、日志）改造成 AI Agent 能直接调用的“记忆系统”，让 Agent 不再只靠大模型临时推理，而是拥有长期、结构化的记忆。
【详细讲给你听】
背景是现在很多企业做 AI Agent 时，发现 Agent 记不住历史对话、查不到历史数据，每次都要重新推理，效率低还容易出错。之前大家用向量数据库存碎片，但没法处理复杂的关系和多种格式的数据。核心是 Lance 团队提出了一套从“数据湖”到“记忆湖”的架构演进方案。他们先把企业里分散的日志、文档、图片、传感器数据统一存到数据湖里，然后通过一套“记忆编排”机制，把这些数据按时间、事件、实体关系组织成 Agent 可检索的记忆块。关键细节有三个：一是他们用了一种叫“时间线索引”的方法，让 Agent 能按时间顺序回溯事件；二是实现了“多模态记忆压缩”，把图片和文本混合压缩成 token 节省存储；三是提出了“记忆衰减”策略，不常用的记忆自动降级，保持检索效率。影响是这套方案让工业场景里的排程 Agent 能记住过去三个月所有订单变更和产线异常，决策准确率提升了 30% 以上。
【关键术语小词典】
- 多模态数据湖：存储文本、图片、音频、日志等多种格式数据的统一仓库。
- Agent 记忆湖：专门为 AI Agent 设计的结构化、可检索的长期记忆系统。
- 时间线索引：按时间顺序组织数据，方便 Agent 回溯历史事件的方法。
- 记忆衰减：自动降低不常用记忆的优先级，保持检索速度和存储成本。
【对你有啥用】
1. 你正在做供应链排程算法，这套“记忆湖”架构可以直接套到你的排产 Agent 上。下次跟客户聊时，可以提“我们能让 Agent 记住过去三个月的订单变更和产线异常，而不是每次重新算”，这比单纯讲算法优化更有说服力。
2. 你关注 AI Agent 落地，这篇文章给了你一个具体的技术路径：不是用向量数据库存碎片，而是用“时间线索引+记忆衰减”来组织工业数据。这改变了你之前对 Agent 记忆“就是向量检索”的理解，可以拿这个思路去跟你们的技术团队讨论架构选型。
3. 你今年想深化工业软件+AI 的理解，这个案例直接展示了“数据湖”到“记忆湖”的演进逻辑，可以帮你跟客户解释为什么 Agent 需要“记忆”而不是“搜索”，这对你写产品文档或做技术宣讲很有用。

- 软件供应链攻击：通过污染开源库或第三方组件，间接攻击使用该软件的企业。
