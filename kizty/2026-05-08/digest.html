【一句话讲清楚它在说啥】
PageIndex是一个开源项目，它放弃传统向量数据库和文本分块，改用类似AlphaGo的树搜索方法，让大模型像人类专家一样推理式地检索长文档，在金融测试集上准确率达98.7%。
【详细讲给你听】
背景是现在做RAG（检索增强生成）基本都靠向量数据库，把文档切成小块算相似度。但问题来了，相似不等于相关。比如你问“这批电池的排产计划受什么原料限制”，向量搜索可能只找到包含“电池”和“原料”的片段，却漏掉上下文里隐含的供应链约束。PageIndex团队受AlphaGo启发，提出一个反直觉的方案：彻底抛弃向量数据库和分块。核心做法分两步，第一步先把文档自动生成一个类似目录的树状索引，第二步让LLM在这个树上做推理式搜索，模拟人类专家翻目录、跳章节、综合判断的过程。关键细节有三个：一是它不需要向量数据库，完全靠文档结构和LLM推理；二是不做人工分块，按自然章节组织；三是在FinanceBench金融文档测试集上达到98.7%准确率，远超传统向量RAG。影响在于，这给工业软件场景里的长文档分析（比如工艺手册、排产约束文档）提供了一个新思路——不用再纠结分块大小和向量维度，直接让模型“读目录找答案”。
【关键术语小词典】
RAG / 检索增强生成：让大模型先检索外部知识再回答，防止胡编乱造。
Vector DB / 向量数据库：把文本转成向量存起来，搜索时找“长得像”的片段。
Agentic / 智能体式：系统能自主规划步骤、调用工具，而不是一次问答就完事。
FinanceBench / 金融基准测试：专门评估模型在金融文档上检索和回答能力的测试集。
【对你有啥用】
第一，这直接挑战了你现在做决策智能平台时“RAG必须用向量库”的默认假设。下次跟电池或钢铁客户聊排产优化，如果对方抱怨“系统查工艺文档总是不准”，你可以提这个新范式：不用向量库，用推理式检索，准确率更高且可解释。第二，对产品设计有启发。PageIndex的“树索引+推理搜索”架构，可以类比到供应链排产里的约束推理——不是简单匹配相似订单，而是像专家一样沿着BOM树逐层推理瓶颈。第三，作为PM，你可以把这个案例写进你的AI Agent学习笔记里，它展示了“Agentic”不只是调工具，而是用结构化索引让模型自己规划检索路径，这对你理解LLM应用的产品边界很有价值。

- State Machine / 状态机：一种编程模型，定义系统在不同状态下的行为转换，让Agent行为可预测。
- Prompt Engineering / 提示词工程：通过精心设计输入文本，引导LLM输出期望结果的技术。
