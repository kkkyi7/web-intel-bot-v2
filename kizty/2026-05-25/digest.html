【一句话讲清楚它在说啥】
一个开发者把AI大神Karpathy指出的LLM编程常见问题，整理成一份CLAUDE.md配置文件，让Claude Code在写代码时不再过度设计、乱改代码、隐藏困惑。
【详细讲给你听】
背景是Karpathy最近发帖吐槽LLM写代码的几个典型毛病：模型会替你做错误假设然后闷头执行、不管理自己的困惑、不寻求澄清、不暴露权衡、过度复杂化代码和API、在只需要100行的地方搞出1000行、还会擅自修改或删除它不完全理解的代码。这个开源项目Multica就把这些观察提炼成四个原则，塞进一个CLAUDE.md文件里，让Claude Code在每次编码前自动加载。核心机制是：第一，先思考再编码，强制模型显式陈述假设、在不确定时提问、在发现更简单方案时反驳。第二，简洁优先，禁止任何超出需求的特性、单次使用的抽象、未要求的灵活性。第三，手术式修改，只动必须改的行，不“顺手”重构相邻代码或注释。第四，目标驱动执行，把“添加验证”变成“先写测试让无效输入失败，再让测试通过”。这个文件已经在GitHub上开源，可以直接作为Claude Code插件安装。
【关键术语小词典】
CLAUDE.md：Claude Code项目根目录下的行为配置文件，类似AI版的.editorconfig。LLM coding pitfalls：大语言模型在编程时常见的错误模式，如过度工程、隐藏假设。Multica：一个开源平台，用于运行和管理可复用的编码代理技能。Karpathy：前OpenAI和Tesla的AI研究总监，以深度学习教学和LLM批判性观察闻名。
【对你有啥用】
第一，你正在做供应链优化的决策智能产品，这个“先暴露假设再执行”的框架可以直接用在排程算法与客户沟通中——让AI在给出排产方案前先列出它假设的产能约束和物料优先级，而不是直接输出一个黑箱结果。第二，你们公司做企业级AI平台，这个CLAUDE.md文件本质上是一个“AI行为约束模板”，你可以借鉴这个思路，为你们的决策智能产品设计类似的“决策行为准则”配置文件，让客户能按行业（电池、医药）定制AI的思考风格。第三，你今年想深化AI Agent理解，这个项目展示了如何用极简的提示工程（一个文件）系统性地修复LLM的常见缺陷，比堆叠复杂RAG流程更值得在内部工具中尝试。

【背景知识】
Karpathy 之前多次吐槽过 LLM 写代码的通病——比如模型会闷头假设、不暴露不确定性、过度工程化，甚至擅自删改它没完全搞懂的代码。这个项目就是把他的吐槽整理成一份 CLAUDE.md 配置文件，让 Claude Code 在每次编码前自动加载这些约束，相当于给 AI 套了个“先想清楚再动手”的行为框架。不过要注意，这种提示工程方案依赖模型对指令的遵循程度，如果 Claude 自己判断某些指令“不相关”就可能跳过（有用户反馈过这个问题），而且它只约束了编码行为，对模型本身的推理能力天花板没有改变。
【社区讨论】
开发者社区对这个配置文件的讨论集中在两个方向：一是有人实测发现 Claude Code 有时会忽略 CLAUDE.md 里的指令，因为它是作为用户消息而非系统配置注入的，模型会自行判断相关性；二是不少人在尝试把类似思路迁移到其他 AI 编码工具（如 Cursor、Copilot），但发现各家对自定义指令的解析机制不同，效果差异很大。

背景：Claude Code 是 Anthropic 推出的命令行编程助手，功能很强但需要付费 API 调用。很多开发者想用它的交互体验，但又不想掏钱或者想用本地模型。核心：这个叫 free-claude-code 的开源项目搭建了一个代理服务器，把 Claude Code 发给 Anthropic 的 API 请求拦截下来，转发到其他 17 个模型提供商，包括 NVIDIA NIM、Google AI Studio、DeepSeek、Ollama 等。关键细节：它支持按模型层级路由，比如把 Opus 请求发给一个提供商，Sonnet 发给另一个。还带一个本地管理后台，可以在网页上配置和验证 API 密钥。安装只需要一行命令，启动后就能用 fcc-claude 命令代替原来的 claude 命令。影响：对开发者来说，这意味着可以白嫖 Claude Code 的交互界面和工具链，底层用免费模型跑。对产品经理来说，这展示了 AI 工具链解耦的趋势——前端体验和后端模型可以完全分离，用户选模型的自由度越来越高。

2. 学习路径：如果你想深入理解 AI Agent 工具链的架构，这个项目的代码值得读一读。它实现了 API 路由、模型选择、流式处理等核心机制，跟企业级 AI 平台的架构设计思路一致。可以 fork 下来跑一遍，理解代理模式在 AI 产品中的应用。

【一句话讲清楚它在说啥】
这篇论文提出了一种叫SkillOpt的方法，能像训练神经网络权重一样，系统性地优化智能体（Agent）的技能文档，通过严格的编辑和验证机制，让技能在多个模型和场景下稳定提升，效果远超人工或一次性生成。
【详细讲给你听】
背景上，现在的智能体技能大多是手工编写、一次性生成或通过松散的自我修改来进化，这就像没有教练的运动员自己瞎练，进步不稳定甚至倒退。核心是，作者认为技能应该被当作冻结智能体的“外部状态”来训练，遵循权重空间优化的纪律。他们提出了SkillOpt，这是一个文本空间优化器，它用一个独立的优化模型，把智能体的执行结果（得分）转化为对技能文档的增、删、改操作，并且只有严格提升验证集分数时才接受修改。关键细节包括：引入了“文本学习率预算”来控制修改幅度，“拒绝编辑缓冲区”避免重复无效修改，以及“慢/元更新”机制让训练更稳定。在六个基准测试、七个目标模型和三种执行框架（直接对话、Codex、Claude Code）上，SkillOpt在所有52个测试组合中都是最优或并列最优。比如在GPT-5.5上，它把直接对话的准确率提升了23.5个百分点，在Codex和Claude Code的循环中也分别提升了24.8和19.1个百分点。更厉害的是，优化后的技能文档在不同模型规模、不同执行环境间迁移时，效果依然保持。
【关键术语小词典】
- SkillOpt / 技能优化器：一种自动改进智能体技能文档的算法，类似给AI技能请了个私人教练。
- Agent Skills / 智能体技能：指导AI如何执行特定任务的一套指令或文档，比如“如何写周报”。
- Text-space optimizer / 文本空间优化器：直接在文字层面进行修改和优化的算法，而不是修改模型内部的数字参数。
- Codex / Claude Code / 代码执行框架：两种让AI模型能写代码并执行的环境，类似AI的程序员工作台。
【对你有啥用】
第一，你正在做决策智能平台，SkillOpt的思路可以直接搬到供应链排程算法的优化上。比如，你可以把一条排产规则看作一个“技能”，用类似的方法自动迭代规则，看哪个规则组合能提升交付准时率，而不是靠人工调参。第二，作为PM，下次跟制造业客户（比如电池厂）聊AI落地时，可以提这个概念：我们不只是给一个模型，而是给一个能自动优化自身决策逻辑的系统，就像给工厂的调度员配了个永不疲倦的优化师。这能直接提升产品的技术壁垒和客户信任。第三，这个方法论对你学习AI Agent很有启发：它打破了“技能只能靠人写”的认知，意味着未来产品中的智能体可以自我进化，你在规划产品路线图时，可以把“技能自动优化”作为一个核心差异化功能来考虑。

ETCHR: Editing To Clarify and Harness Reasoning
arXiv · Beichen Zhang, Yuhong Liu, Jinsong Li, Yuhang Zang, Jiaqi Wang, Dahua Lin · 3 天前

【一句话讲清楚它在说啥】
多模态大模型做视觉推理时，纯文字思维链不够用。这篇论文提出一个专门的图像编辑模型ETCHR，在推理过程中动态编辑图片来辅助思考，让模型在多个视觉任务上准确率提升4-5个百分点。
【详细讲给你听】
背景是这样的：现在多模态大模型（比如能看图的GPT-4V）做视觉推理时，通常先用文字描述图片内容，然后再推理。但遇到需要精细观察或变换视角的问题，文字描述会丢失细节。有人尝试让模型直接“用图像思考”，但现有方法要么只能调用固定的工具（比如画框、涂色），要么生成的中间图片噪声太大。ETCHR走第三条路：用一个专门的图像编辑模型，把它和推理模型解耦开。核心创新是发现两个关键缺口：语言侧缺口——普通编辑器只会被动执行指令，不会把抽象问题转化成合适的视觉变换；生成侧缺口——推理步骤越多，编辑质量越差。ETCHR用两阶段训练解决：先用推理模仿（监督微调编辑轨迹），再用推理增强（用VLM奖励信号优化编辑正确性和推理准确率）。由于编辑器是解耦的，可以直接插到不同模型里用，无需额外训练。在五个任务族（精细感知、图表理解、逻辑推理、拼图恢复、3D理解）上，搭配Qwen3-VL-8B平均提升4.82%，搭配Gemini-3.1-Flash-Lite提升5.47%，搭配万亿参数MoE模型Kimi K2.5提升4.61%。
【关键术语小词典】
- MLLM / 多模态大语言模型：能同时处理文本和图像的大模型，比如GPT-4V。
- Pass@1：模型第一次尝试就给出正确答案的概率。
- MoE / 混合专家模型：把大模型拆成多个“专家”子网络，每次只激活部分专家，提高效率。
- VLM / 视觉语言模型：能理解图像和文本之间关系的模型，常用于生成奖励信号。
【对你有啥用】
第一，你做的决策智能平台如果涉及视觉数据（比如工厂质检图像、供应链中的图纸识别），这个思路可以直接用：用专门的编辑模型预处理图像，再喂给推理模型，比让模型自己“硬想”效果好。第二，对产品设计有启发：你开发排程算法时，用户输入的数据（比如BOM表、工艺路线）可能也需要“编辑澄清”——不是直接改数据，而是用算法自动补充缺失信息或转换视角，让后续决策更准。第三，论文里“解耦编辑与推理”的架构设计，值得你在做AI Agent产品时参考：把复杂任务拆成专门的子模块，比用一个全能模型更可控、更易维护。

【背景知识】
多模态大模型做视觉推理时，纯文本思维链会丢失像素级细节，比如要数清图片里螺丝的个数或判断两个零件是否对齐。之前有人试过让模型自己画框、涂色来辅助思考，但要么只能调用固定工具，要么生成的中间图噪声太大。ETCHR 的思路是把“编辑图片”和“推理”拆成两个独立模块——用一个专门的图像编辑模型在推理过程中动态修改图片，而不是让推理模型硬扛。不过这种解耦设计也有代价：编辑模型本身需要额外训练，而且如果编辑步骤太多，后续编辑质量会明显下降，论文里也提到这是当前的主要瓶颈。
