【一句话讲清楚它在说啥】
Presenton是一个完全开源的AI演示文稿生成工具，支持本地部署或桌面应用，可接入OpenAI、Claude等多种模型，让你自己控制数据和模型，无需订阅付费。
【详细讲给你听】
背景是现在主流的AI做PPT工具比如Gamma、Beautiful AI都是SaaS订阅制，数据上传到别人服务器，模型选择也受限。Presenton直接对标这些产品，但走完全开源路线。核心是它提供了两种使用方式：一是通过Docker自托管部署到自己的服务器，二是直接下载Mac/Windows/Linux桌面应用。关键细节有三个：第一，它支持几乎所有主流模型提供商，包括OpenAI、Gemini、Vertex AI、Azure OpenAI、Anthropic Claude，甚至可以用Ollama跑本地开源模型，真正做到“自带密钥”按用量付费。第二，它内置了MCP服务器，这意味着可以通过模型上下文协议直接生成演示文稿，对开发者来说是一个可编程的API接口。第三，导出格式是标准PPTX和PDF，而且支持自定义HTML+Tailwind CSS模板，甚至可以从现有PowerPoint文档生成模板。影响在于，对于企业用户尤其是制造业客户，数据隐私和模型可控性是刚需，这个工具直接解决了“用AI做PPT但数据不能出内网”的痛点。
【关键术语小词典】
MCP Server / 模型上下文协议服务器：一种让AI模型之间通信和协作的标准化接口。BYOK / 自带密钥：用户使用自己的API密钥调用模型，不依赖平台内置的付费订阅。Ollama / 本地模型运行工具：可以在个人电脑上运行开源大语言模型的轻量级框架。
【对你有啥用】
第一，你服务的电池、医药、钢铁客户对数据隐私极其敏感，下次跟客户演示决策智能平台时，可以用Presenton自托管方案来类比“我们的AI排产方案也可以完全部署在你们内网，数据不出厂区”。第二，作为PM，你可以用Presenton快速生成产品方案PPT，尤其是接入Claude或本地模型后，能直接对比不同模型在生成工业场景演示时的效果差异，这对你理解LLM应用落地很有价值。第三，它内置的MCP Server和API能力，可以启发你思考：你们的决策智能平台是否也可以提供类似的“模型无关”API接口，让客户自由选择底层AI引擎？

【一句话讲清楚它在说啥】
Anthropic 产品负责人 Boris 接受采访，承认 Claude 的限速策略是故意的，目的是筛选出真正重度、高价值的用户，而不是讨好所有免费或轻度使用者。
【详细讲给你听】
背景是 Claude 一直因为 API 调用限速、免费版对话次数少被用户吐槽。很多人觉得 Anthropic 太小气，不如 OpenAI 大方。但 Boris 这次直接摊牌：限速不是技术问题，是产品策略。核心逻辑是，最挑剔的用户——比如开发者、企业客户、高频写代码的人——反而会因为限速而更珍惜每次调用，更愿意付费升级。他们发现，限速后用户留存率反而上升了，因为留下来的都是真正需要 Claude 的人。关键细节有两个：一是 Anthropic 内部数据表明，限速后重度用户的月活时长增加了 20% 以上；二是他们专门针对“抱怨最多”的用户做了调研，发现这些人其实是最离不开 Claude 的，只是嘴上骂。机制上，这有点像健身房会员卡——故意设置入场门槛，反而让买了年卡的人更频繁来练。对产品经理来说，这颠覆了“用户体验就是越快越好”的直觉，转而强调“筛选用户”比“讨好所有人”更重要。
【关键术语小词典】
- Anthropic / 无标准中文译名：OpenAI 的主要竞争对手，Claude 模型的开发公司。
- Boris / 无标准中文译名：Anthropic 的产品负责人，负责 Claude 的产品策略。
- 限速 / Rate Limiting：API 或免费版中限制用户每分钟/每天可调用的次数。
【对你有啥用】
1. 直接启发你的产品策略。你做的决策智能平台，如果客户觉得“算得太慢”或“API 调用太贵”，可以借鉴这个思路：不是无脑加算力，而是通过限速或分层定价，筛选出真正愿意为精度付费的制造业客户。比如对电池排产算法，可以给免费试用版限制求解次数，让重度客户主动升级。
2. 跟客户沟通时可以用。下次跟电池或医药客户聊，可以提“Anthropic 发现最挑剔的用户反而最离不开他们”，来解释为什么你的平台某些功能需要付费解锁。这比直接说“我们成本高”更有说服力。
3. 对你学习 AI Agent 和 LLM 应用有直接参考。你在研究开发者工具，Claude 的限速策略告诉你：工具产品的核心不是“功能最多”，而是“让对的人留下来”。你在设计 Agent 的调用频率或 token 限制时，可以故意设置“摩擦点”来过滤低价值请求。

这场圆桌讨论认为，纯套壳大模型的应用活不长，下一个百亿级AI产品必须是长期在线、能连接物理世界的入口，比如AI眼镜或具身机器人，核心是“多模态底座+AI原生智能体+可穿戴硬件”三位一体。
【详细讲给你听】
背景是现在AI产品大多还停留在聊天框里，比如ChatGPT，在线时间短，跟物理世界没连接。圆桌嘉宾来自乐奇和商汤，他们一致认为，单纯套壳大模型的应用注定短命，因为没法形成真实交互闭环。核心观点是：下一个杀手级AI产品必须是长期在线的入口，能高频、刚需地连接物理世界。目前看，AI眼镜最合适，因为人每天看世界的时间比看手机长，眼镜能持续在线。关键细节有两个：第一，嘉宾区分了有显示和无显示的AI眼镜，有显示（比如AR）能实时把AI处理结果呈现在视野中，完成交互闭环，比如导航、巡检，视觉带宽比语音高太多；第二，商业模式分三层：硬件大规模销售是入口，然后生态拓展（比如开发者做“比价”应用），最后是长期智能体服务。影响是，这给产品人一个明确信号：别再做纯软件套壳，要往硬件+智能体+多模态方向走，才能抓住下一波机会。
【关键术语小词典】
- 多模态底座：能同时处理文字、图像、语音等多种信息的大模型基础能力。
- 具身智能：AI拥有物理身体（如机器人），能在真实世界感知和行动。
- AI Agent：能自主执行任务的智能体，比如帮你比价、订餐。
【对你有啥用】
1. 产品判断：你做的决策智能平台（排程算法）本质也是“连接物理世界”的Agent。圆桌强调“长期在线+真实交互闭环”，这正好对应你的供应链优化场景——排产算法需要实时感知产线状态（物理世界），然后给出决策。可以思考：你的产品能否从“离线优化”升级为“持续在线的决策Agent”？比如让算法实时接入MES系统，自动调整排程。
2. 客户沟通：下次跟电池、医药客户聊时，可以提“AI眼镜在巡检、提醒场景的价值”，这能帮你打开新场景。客户关心降本增效，你可以说“AI眼镜+你的排程算法，能让现场工人实时看到最优操作指令”，这比纯软件方案更直观。
3. 学习路径：你今年想深化AI Agent理解，这篇圆桌给了具体方向：研究“多模态+硬件”的交互闭环。建议你关注商汤的多模态产品落地，以及乐奇的OS生态策略，这能帮你理解工业场景下“AI如何从数字世界走进物理世界”。
